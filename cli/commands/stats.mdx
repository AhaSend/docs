AhaSend CLI `stats` commands report email counts and delivery, bounce and delivery-time statistics; this page covers filters and output.

Before running the examples, [log in](/cli/authentication) with an API key that has the `statistics:read:all` [scope](/api-reference/scopes#statistics-and-reports), and replace `example.com` in `--sender-domain` with one of your sending domains.

## Overview

```text
ahasend stats [subcommand] [flags]
```

Available subcommands:
- `deliverability` - Message counts and delivery and open rates per period
- `bounces` - Bounces per period by classification
- `delivery-time` - Average delivery time per period and per recipient domain
- `emails` - Email counts of any period, for the whole account or per domain

[`emails`](#email-counts) has its own flags. `deliverability`, `bounces` and `delivery-time` take these:

- `--from-time`: Start time. The default is `7d`, 7 days ago. An empty value leaves the start to the API.
- `--to-time`: End time. Without it, the API uses now.
- `--group-by`: `hour`, `day` (the default), `week` or `month`.
- `--sender-domain`: Filter by sender domain.
- `--recipient-domain`: Filter by recipient domain.
- `--tag`: Filter by message tag. A tag cannot hold a comma.

`--from-time` and `--to-time` take an RFC 3339 time, such as `2026-09-01T00:00:00Z`, or a relative time that counts back from now, such as `24h`, `7d` or `3mo`. `--from-time` must be before `--to-time`. With the default `--from-time`, a `--to-time` more than 7 days ago fails, so give an earlier `--from-time` too. An invalid time fails before any request is sent, with exit code 4.

`--sender-domain`, `--recipient-domain` and `--tag` can be used multiple times, or take values separated by commas. The CLI sends only the filters you give.

For `deliverability`, `bounces` and `delivery-time`, `--output json` prints the API's response unchanged. Table and plain output show each period's time in your local time zone. `--output csv` writes one row per period, or per classification or recipient domain where the report has them.

## Deliverability statistics

Each period shows how many messages were received, delivered, deferred, bounced, failed, suppressed, opened and clicked. The CLI works out the delivery rate (delivered out of received) and the open rate (opened out of delivered) from these counts.

```bash
# The last 7 days, by day
ahasend stats deliverability

# A fixed date range
ahasend stats deliverability \
  --from-time 2026-09-01T00:00:00Z \
  --to-time 2026-10-01T00:00:00Z

# The last 24 hours, by hour, for one sender domain
ahasend stats deliverability \
  --from-time 24h \
  --group-by hour \
  --sender-domain example.com

# Two recipient domains
ahasend stats deliverability \
  --recipient-domain gmail.com \
  --recipient-domain googlemail.com
```

### Export to CSV

```bash
ahasend stats deliverability --from-time 30d --output csv > deliverability-report.csv
```

## Bounce analysis

Each period shows its bounces by classification, with each classification's count and its share of the period's bounces. `ahasend stats bounces --help` describes the common classifications:

| Classification | Meaning |
|---|---|
| `AuthenticationFailed` | Message rejected due to DMARC or authentication issues |
| `BadConnection` | The connection to the recipient server or its TLS failed |
| `BadDomain` | The recipient domain doesn't exist |
| `DNSFailure` | The domain's MX record is invalid |
| `InactiveMailbox` | The mailbox provider has deactivated the email address |
| `InvalidRecipient` | The email address doesn't exist |
| `PolicyRelated` | Blocked due to recipient server policies (spam or blocklists) |
| `ProtocolErrors` | SMTP communication issues with the recipient mail server |
| `QuotaIssues` | The recipient's mailbox is full |
| `RoutingErrors` | The recipient mail server couldn't route the email |
| `TransientFailure` | The recipient server temporarily rejected the message |
| `Uncategorized` | Other bounce types not specifically categorized |

The API may return other classifications too; the output shows each as the API names it. See [bounce statistics](/api-reference/reports/get-bounce-report).

```bash
# The last 7 days, by day
ahasend stats bounces

# The last 30 days, by week
ahasend stats bounces --from-time 30d --group-by week

# One sender domain, exported to CSV
ahasend stats bounces --sender-domain example.com --from-time 30d --output csv
```

## Delivery time performance

Each period shows the average delivery time, and the time for each recipient domain with the number of delivered messages it covers. Table and plain output give each time in seconds, minutes or hours, whichever reads best. CSV output gives times in seconds, as the API sends them.

```bash
# The last 7 days, by day
ahasend stats delivery-time

# The last 24 hours, by hour, for two recipient domains
ahasend stats delivery-time \
  --from-time 24h \
  --group-by hour \
  --recipient-domain gmail.com \
  --recipient-domain outlook.com
```

## Email counts

`stats emails` shows the email counts of any period in the account's history, for the whole account or for each of its domains. Unlike the other `stats` commands, it is not limited to the account's [message metadata retention](/retention#message-data-vs-metadata) period. It needs CLI v0.5.0 or later.

Each period shows how many messages were received (accepted by AhaSend, inbound mail included), delivered, bounced and suppressed, how many spam complaints came in, and how many temporary delivery failures (deferred), opens and clicks there were. Deferred, opened and clicked count events, so one message can add more than one; `stats deliverability` counts messages, so its numbers differ. Opens and clicks are not fully accurate: AhaSend makes a reasonable effort to filter out bots and scanners. The counts cover transactional, campaign and inbound mail, with inbound mail under the domain that received it, and include deleted domains. Sandbox mail is not counted.

```bash
# Daily counts of today and the 30 days before it
ahasend stats emails

# Monthly counts of 2025 for each domain
ahasend stats emails \
  --from-time 2025-01-01T00:00:00Z \
  --to-time 2026-01-01T00:00:00Z \
  --group-by month \
  --breakdown domain

# Weekly counts of one domain over the last 90 days
ahasend stats emails --from-time 90d --group-by week --sender-domain example.com
```

`stats emails` takes `--from-time`, `--to-time`, `--group-by` and `--sender-domain`, but not `--recipient-domain` or `--tag`. Without `--from-time`, the range starts 30 days before its end, and without `--to-time`, it ends now. Without `--sender-domain`, the counts cover every domain the API key can read. Periods are in UTC, and weeks start on Monday. The range includes `--from-time` and excludes `--to-time`, and the API rounds it out to whole periods. A range can be at most 31 days with `--group-by hour`, 366 days with `day` and `week`, and 5 years with `month`.

`--breakdown domain` shows the counts of each domain, and the command fetches every page of domains and shows them as one result. When a page covers another range than the first page, as when the current period ends while the pages are fetched without a `--to-time`, the command fails with exit code 1 rather than mix ranges: run it again, or give a `--to-time` in the past.

Table and plain output show each period's time in your local time zone. They show the totals of the whole range, then each row: a period, or with a breakdown, a period of one domain. The rows of a breakdown can add up to a few events more or less than the totals. CSV output has a line per row and no line for the totals; its columns are `from_timestamp`, `to_timestamp`, `sender_domain`, empty without a breakdown, and the counters with the API's names, such as `reception_count`. JSON output is the API's response; with a breakdown, one response with the rows of every page and `pagination.has_more` false.

## Filter by tag

```bash
# Messages tagged campaign-summer
ahasend stats deliverability --tag campaign-summer --from-time 30d

# Filter by two tags
ahasend stats deliverability --tag welcome --tag onboarding
```

## Command flags

These flags come from the CLI's `--help`. All commands also accept the [global flags](/cli/configuration#global-flags).

### `stats bounces`

| Flag | Description and default |
|---|---|
| `--from-time string` | Start time (RFC3339, or relative like '7d' or '24h' for 7 days or 24 hours ago; empty leaves it to the API) (default "7d") |
| `--group-by string` | Group results by: hour, day, week or month (default "day") |
| `--recipient-domain strings` | Filter by recipient domain (can be used multiple times) |
| `--sender-domain strings` | Filter by sender domain (can be used multiple times) |
| `--tag strings` | Filter by message tag, none with a comma (can be used multiple times) |
| `--to-time string` | End time (RFC3339, or relative like '1d' for 1 day ago; empty leaves it to the API, which uses now) |

### `stats deliverability`

| Flag | Description and default |
|---|---|
| `--from-time string` | Start time (RFC3339, or relative like '7d' or '24h' for 7 days or 24 hours ago; empty leaves it to the API) (default "7d") |
| `--group-by string` | Group results by: hour, day, week or month (default "day") |
| `--recipient-domain strings` | Filter by recipient domain (can be used multiple times) |
| `--sender-domain strings` | Filter by sender domain (can be used multiple times) |
| `--tag strings` | Filter by message tag, none with a comma (can be used multiple times) |
| `--to-time string` | End time (RFC3339, or relative like '1d' for 1 day ago; empty leaves it to the API, which uses now) |

### `stats delivery-time`

| Flag | Description and default |
|---|---|
| `--from-time string` | Start time (RFC3339, or relative like '7d' or '24h' for 7 days or 24 hours ago; empty leaves it to the API) (default "7d") |
| `--group-by string` | Group results by: hour, day, week or month (default "day") |
| `--recipient-domain strings` | Filter by recipient domain (can be used multiple times) |
| `--sender-domain strings` | Filter by sender domain (can be used multiple times) |
| `--tag strings` | Filter by message tag, none with a comma (can be used multiple times) |
| `--to-time string` | End time (RFC3339, or relative like '1d' for 1 day ago; empty leaves it to the API, which uses now) |

### `stats emails`

| Flag | Description and default |
|---|---|
| `--breakdown string` | Break the counts down by: domain |
| `--from-time string` | Start time, included (RFC3339, or relative like '90d' for 90 days ago; without it, the API starts 30 days before the end) |
| `--group-by string` | Group results by: hour, day, week or month (without it, the API groups by day) |
| `--sender-domain strings` | Count only this domain of the account (can be used multiple times) |
| `--to-time string` | End time, excluded (RFC3339, or relative like '1d' for 1 day ago; without it, the API ends the range now) |
