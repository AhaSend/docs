AhaSend CLI `webhooks` commands let you manage, forward and trigger email event webhooks; this page lists their arguments and flags. For the complete local testing workflow, use the [webhook testing guide](/cli/webhook-testing). For dashboard setup, see [the webhooks guide](/integrations/webhooks).

Before running the examples, [log in](/cli/authentication) with an API key that has the read, write and delete [webhook scopes](/api-reference/scopes#webhook-management) for all domains, and replace `YOUR_RESOURCE_ID` with the ID of one of your webhooks. In the `--domains` examples, replace `example.com` and `example.org` with domains in your account; for any other domain, the API answers 400 `invalid domain: <domain>`. The contact event examples need the scopes and the account that [contact events](#contact-events) describes.

## Overview

```text
ahasend webhooks [subcommand] [flags]
```

Available subcommands:
- `list` - List webhooks
- `create` - Create a webhook
- `get` - Get a webhook
- `update` - Update a webhook
- `delete` - Delete a webhook
- `listen` - Listen for webhook events in real-time
- `trigger` - Trigger webhook events for testing

`webhooks get`, `webhooks update`, `webhooks delete` and `webhooks trigger` take the webhook ID as their positional argument. A webhook ID that is not a UUID fails with exit code 4 before any request. Find IDs with `ahasend webhooks list`.

## Event Types

`--events` on `list`, `create`, `update`, `listen` and `trigger` takes each event by its key or by its type, such as `delivered` or `message.delivered`. See the [event reference](/api-reference/webhooks) for the payloads.

| Event key | Event type | Description |
|---|---|---|
| `reception` | `message.reception` | Email received by AhaSend |
| `delivered` | `message.delivered` | Email delivered to recipient |
| `transient_error` | `message.transient_error` | Temporary delivery failure |
| `failed` | `message.failed` | Permanent delivery failure |
| `bounced` | `message.bounced` | Email bounced |
| `suppressed` | `message.suppressed` | Email suppressed |
| `opened` | `message.opened` | Email opened by recipient |
| `clicked` | `message.clicked` | Link clicked in email |
| `unsubscribed` | `message.unsubscribed` | Recipient unsubscribed through a campaign email |
| `complained` | `message.complained` | Campaign email reported as spam |
| `suppression_created` | `suppression.created` | New suppression added |
| `suppression_deleted` | `suppression.deleted` | Suppression deleted |
| `dns_error` | `domain.dns_error` | DNS configuration error for a domain |
| `sending_type_changed` | `domain.sending_type_changed` | Sending type of a domain changed between transactional and marketing |
| `contact_created` | `contact.created` | Contact created |
| `contact_updated` | `contact.updated` | A field of a contact changed |
| `contact_deleted` | `contact.deleted` | Contact deleted |
| `contact_added_to_list` | `contact.added_to_list` | Contact added to a list |
| `contact_removed_from_list` | `contact.removed_from_list` | Contact removed from a list |
| `contact_subscribed` | `contact.subscribed` | Contact's list subscription confirmed, or its unsubscribe from all lists cleared |
| `contact_unsubscribed` | `contact.unsubscribed` | Contact unsubscribed from a list, or from all lists |
| `contact_complained` | `contact.complained` | Contact reported a campaign email as spam |

`unsubscribed`, `complained`, `suppression_deleted` and the contact events need CLI v0.4.0 or later, and `sending_type_changed` needs CLI v0.5.0 or later.

`--events` can be given several times, and each value can hold several events separated by commas, so `--events delivered,bounced` is the same as `--events delivered --events bounced`. An unknown event, or the same event given twice (by its key, its type or both), fails with exit code 4 before any request.

### Contact Events

The last eight events of the table are the contact events. They need an account with the marketing features, and an API key with the `contacts:read` scope, and `lists:read` as well for `contact_added_to_list`, `contact_removed_from_list`, `contact_subscribed`, `contact_unsubscribed` and `contact_complained`. The API checks the key for every event an enabled webhook has on, so a change to such a webhook needs these scopes even when it names no event. See [contact events](/api-reference/webhooks#contact-events) for what they report.

On `create`, `update` and `trigger`, `--all-events` selects every event except the contact events: the 14 events any account can use. `--all-contact-events` selects the eight contact events. The two can be used together, and neither with `--events`. `--all-contact-events` needs CLI v0.4.0 or later.

## Origins

A webhook's origins pick whose changes its contact and suppression events report: `recipient` (the contact or recipient, through an unsubscribe or a spam complaint), `api`, `dashboard` or `system` (AhaSend). Message events, `dns_error` and `sending_type_changed` have no origin, and a webhook always gets them. See [origin](/api-reference/webhooks#origin).

`--origins` on `create` and `update` takes origins as `--events` takes events: several times, or separated by commas. Without it, `create` leaves the origins out, and the webhook gets every origin. On `update`, `--origins` replaces the origins, and `--all-origins` gives the webhook every origin again, since the API keeps the stored origins when a request names none; the two cannot be combined. `--origins` and `--all-origins` need CLI v0.4.0 or later.

`webhooks get` shows the origins after the events, and CSV output has an `origins` column after `events`. For a webhook that gets every origin, table and plain output show `all`, and CSV output an empty cell. A table of webhooks has no origins column.

## List Webhooks

```bash
# List all webhooks
ahasend webhooks list

# List webhooks with JSON output
ahasend webhooks list --output json

# List only the enabled webhooks
ahasend webhooks list --enabled

# List only the disabled webhooks
ahasend webhooks list --enabled=false

# List only the webhooks that get contact.created
ahasend webhooks list --events contact_created
```

`--events` lists only the webhooks that have every event it names on, and needs CLI v0.4.0 or later. The API applies the `--enabled` and `--events` filters, so a page holds up to `--limit` matching webhooks. Pages work as [Lists and Pagination](/cli/configuration#lists-and-pagination) describes.

## Create Webhook

```bash
# Create a webhook for three events of every domain
ahasend webhooks create \
  --name "Main app webhook" \
  --url https://app.example.com/webhooks/ahasend \
  --scope global \
  --events delivered,bounced,failed

# Create a webhook for one domain, with every event except the contact events
ahasend webhooks create \
  --name "Example webhook" \
  --url https://api.example.com/webhooks/example \
  --scope scoped --domains example.com \
  --all-events

# Create a webhook for the contact events of changes made through the API
ahasend webhooks create \
  --name "Contact sync" \
  --url https://app.example.com/webhooks/contacts \
  --all-contact-events --origins api

# Create a disabled webhook
ahasend webhooks create \
  --name "Test webhook" \
  --url https://test.example.com/webhook \
  --events delivered \
  --enabled=false
```

- `--name` and `--url` are required. When one is missing and stdin is a terminal, the command asks for it. With `--non-interactive`, or when stdin is not a terminal, a missing value fails with exit code 4.
- On a terminal, without `--events`, `--all-events` or `--all-contact-events`, the command also asks for the events, and lists them. Answer with events separated by commas, or with `all`, which selects every event except the contact events, as `--all-events` does. A webhook created without events receives none until `webhooks update` gives it some.
- `--scope` is `global` unless you set it. A global webhook receives the events of every domain. A `scoped` webhook receives only the events of the domains you give with `--domains`, which it requires. `--domains` without `--scope scoped` fails with exit code 4.
- A webhook is enabled unless you set `--enabled=false`.
- `--url` must be an HTTP or HTTPS URL with a host name and no user name or password. Use HTTPS in production: a plain HTTP URL for a host other than `localhost` or a loopback address prints a warning on stderr.

The output shows the webhook's secret once. Save it to [verify the webhook's signatures](/api-reference/webhooks/security); `webhooks get` does not show it.

## Get Webhook

Show a webhook's name, URL, status, events, origins, scope and domains, its timestamps and its call counters (successful calls, failed calls, errors since the last success and the last call time). The output has no secret: the API returns it only when you create the webhook.

```bash
ahasend webhooks get YOUR_RESOURCE_ID

# Save the webhook's configuration as JSON
ahasend webhooks get YOUR_RESOURCE_ID --output json > webhook-backup.json
```

## Update Webhook

Only the flags you set are sent, and other settings stay as they are, except that the event flags set the whole list of events (see the warning below). Give at least one flag.

```bash
# Change the name and URL
ahasend webhooks update YOUR_RESOURCE_ID \
  --name "Updated webhook" \
  --url https://new-endpoint.example.com/webhook

# Enable the webhook and replace its events
ahasend webhooks update YOUR_RESOURCE_ID \
  --enabled --events delivered,bounced,opened

# Disable the webhook
ahasend webhooks update YOUR_RESOURCE_ID --enabled=false

# Select every event, the contact events included
ahasend webhooks update YOUR_RESOURCE_ID --all-events --all-contact-events

# Remove every event
ahasend webhooks update YOUR_RESOURCE_ID --clear-events

# Get the contact and suppression events of changes made through the API only
ahasend webhooks update YOUR_RESOURCE_ID --origins api

# Get them from every origin again
ahasend webhooks update YOUR_RESOURCE_ID --all-origins

# Limit the webhook to two domains
ahasend webhooks update YOUR_RESOURCE_ID \
  --scope scoped --domains example.com,example.org

# Remove the domain restriction
ahasend webhooks update YOUR_RESOURCE_ID --scope global
```

<Warning>
On CLI v0.4.0 or later, the event flags set the webhook's whole list of events: every event they do not name is turned off, including a contact event turned on in the dashboard. On CLI v0.5.0 or later, this includes `sending_type_changed`. To keep an event, name it too.
</Warning>

- `--events` gives the webhook the events it names, and `--all-events` and `--all-contact-events` select events as [Contact Events](#contact-events) describes. `--clear-events` turns every event off, and cannot be combined with the other event flags.
- `--origins` and `--all-origins` change the origins, as [Origins](#origins) describes.
- `--domains` replaces the domains of a scoped webhook. The API ignores it on a global webhook unless you also give `--scope scoped`. `--scope global --domains <domain>` fails with exit code 4.
- `--scope global` removes the domain restriction.

## Delete Webhook

```bash
# Delete with a confirmation prompt
ahasend webhooks delete YOUR_RESOURCE_ID

# Skip the confirmation prompt
ahasend webhooks delete YOUR_RESOURCE_ID --force
```

The command asks for confirmation first, as [Prompts](/cli/configuration#prompts) describes; `--force` (`-f`) skips it. A deleted webhook cannot be restored.

## Listen for Events

`webhooks listen` streams webhook events to your terminal over a WebSocket connection, and can forward each event to a local endpoint. It prints events as text, whatever `--output` says, and runs until you press Ctrl+C or the connection closes.

```bash
# Listen through a temporary webhook
ahasend webhooks listen

# Listen through an existing webhook
ahasend webhooks listen --webhook-id YOUR_RESOURCE_ID

# Show only opens and clicks, and forward them to a local server
ahasend webhooks listen \
  --events message.opened,message.clicked \
  --forward-to http://localhost:3000/webhook
```

The API key needs the `webhooks:write:all` scope. Without `--webhook-id`, the API creates a temporary webhook that stays after the command ends. Forwarded events are signed with a forwarding secret that the command prints when it connects. The [webhook testing guide](/cli/webhook-testing) covers temporary webhooks, forwarding, signatures and exit codes.

The stream sends only the events that the API key's scopes can read. On CLI v0.4.0 or later, for each family of events the webhook turns on whose read scope the key does not have, the command prints the server's warning on stderr as it connects, such as `Warning: The API key does not have the suppressions:read scope, so suppression events are not sent to this stream`.

## Trigger Test Events

`webhooks trigger` asks the API to send test events to a webhook, so you can test your endpoint without waiting for real email events.

```bash
# Trigger one event
ahasend webhooks trigger YOUR_RESOURCE_ID --events message.delivered

# Trigger several events
ahasend webhooks trigger YOUR_RESOURCE_ID \
  --events message.delivered,message.opened,message.clicked

# Trigger every event except the contact events
ahasend webhooks trigger YOUR_RESOURCE_ID --all-events

# Trigger the contact events
ahasend webhooks trigger YOUR_RESOURCE_ID --all-contact-events
```

Give `--events`, `--all-events` or `--all-contact-events`. `--all-events` and `--all-contact-events` together trigger all 22 events. Without an event flag, the command fails with exit code 4. The output is the API's message. A disabled webhook gets no events: the API answers that they are queued, and then drops them. Enable the webhook first with `ahasend webhooks update YOUR_RESOURCE_ID --enabled`.

## Command Flags

These flags come from the CLI's `--help`. All commands also accept the [global flags](/cli/configuration#global-flags).

### `webhooks create`

| Flag | Description and default |
|---|---|
| `--all-contact-events` | Select every contact event |
| `--all-events` | Select every event except the contact events |
| `--domains strings` | Domain a scoped webhook is limited to (can be used multiple times) |
| `--enabled` | Enable the webhook (the API enables it when omitted) (default true) |
| `--events strings` | Event type, such as `delivered` or `message.delivered` (can be used multiple times) |
| `--idempotency-key string` | Idempotency key for safe retries (generated when omitted) |
| `--name string` | Webhook name (required) |
| `--non-interactive` | Never prompt; fail when a required flag is missing |
| `--origins strings` | Origin whose contact and suppression events the webhook gets: `recipient`, `api`, `dashboard` or `system`; every origin when not set (can be used multiple times) |
| `--scope string` | Webhook scope: `global` or `scoped` (default `global`) |
| `--url string` | Webhook URL (required) |

### `webhooks delete`

| Flag | Description and default |
|---|---|
| `-f`, `--force` | Skip confirmation prompt |

### `webhooks get`

This command has no command-specific flags. See [global flags](/cli/configuration#global-flags).

### `webhooks list`

| Flag | Description and default |
|---|---|
| `--after string` | Return the page after this cursor |
| `--before string` | Return the page before this cursor |
| `--enabled` | Filter by enabled (`--enabled`) or disabled (`--enabled=false`) state |
| `--events strings` | List only the webhooks with this event on, such as `delivered` or `message.delivered` (can be used multiple times) |
| `--limit int32` | Maximum number of items to return (0-100; 0 uses the API default) |

### `webhooks listen`

| Flag | Description and default |
|---|---|
| `--events strings` | Show only this event type, such as `message.opened` or `opened` (can be used multiple times) |
| `--forward-to string` | Local endpoint to forward events to |
| `--skip-verify` | Skip SSL certificate verification for local endpoints when forwarding events (needs `--forward-to`) |
| `--slim-output` | Slim down the payload for printing to the console |
| `--webhook-id string` | Use existing webhook instead of creating temporary one |

### `webhooks trigger`

| Flag | Description and default |
|---|---|
| `--all-contact-events` | Select every contact event |
| `--all-events` | Select every event except the contact events |
| `--events strings` | Event type to trigger, such as `message.delivered` or `delivered` (can be used multiple times) |

### `webhooks update`

| Flag | Description and default |
|---|---|
| `--all-contact-events` | Select every contact event |
| `--all-events` | Select every event except the contact events |
| `--all-origins` | Get the contact and suppression events of every origin |
| `--clear-events` | Remove every event type |
| `--domains strings` | Domain restriction, replacing all domains (can be used multiple times) |
| `--enabled` | Enable (`--enabled`) or disable (`--enabled=false`) the webhook |
| `--events strings` | Event type, such as `delivered` or `message.delivered`, replacing all event types (can be used multiple times) |
| `--name string` | New webhook name |
| `--origins strings` | Origin whose contact and suppression events the webhook gets: `recipient`, `api`, `dashboard` or `system`, replacing all origins (can be used multiple times) |
| `--scope string` | New webhook scope: `global` or `scoped` |
| `--url string` | New webhook URL |
