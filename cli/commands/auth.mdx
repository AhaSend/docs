The `auth` command manages authentication credentials and profiles for the AhaSend CLI.

Before running the examples, [log in with a full API key](/cli/authentication), use your verified sender domain, and replace `YOUR_RESOURCE_ID` with a resource UUID from your test account. Create any named template, recipient, attachment, or JSON files first. Shell examples use Bash; examples that read JSON with `jq` need jq installed. Sends use sandbox mode.

## Overview

```text
ahasend auth [subcommand] [flags]
```

Available subcommands:
- `login` - Authenticate with AhaSend
- `status` - Show authentication status
- `switch` - Switch between profiles
- `logout` - Remove authentication

## Login

Authenticate with your AhaSend API credentials:

### Interactive Login

```bash
ahasend auth login
```

You'll be prompted for:
- API Key
- Account ID
- Profile name (optional)

### Direct Login

```bash
ahasend auth login \
  --api-key YOUR_API_KEY \
  --account-id YOUR_ACCOUNT_ID \
  --profile production
```


## Status

Check current authentication status and available profiles:

```bash
ahasend auth status
```

The output shows the active profile, account ID, API URL, and available profiles.

JSON output for scripting:
```bash
ahasend auth status --output json
```

## Switch

Change the active profile:

```bash
# Switch to staging profile
ahasend auth switch staging

# Confirm switch
ahasend auth status
```

## Logout

Remove authentication credentials:

```bash
# Remove the named test profile without a confirmation prompt
ahasend auth login --profile docs-logout-test
ahasend auth logout docs-logout-test
# Re-create and remove the test profile
ahasend auth login --profile docs-logout-test
ahasend auth logout docs-logout-test
```

## Profile Management

### Multiple Environments

Set up profiles for different environments:

```bash
# Production
ahasend auth login --profile production

# Staging
ahasend auth login --profile staging

# Development
ahasend auth login --profile development
```

### Using Profiles

```bash
# Use specific profile for a command
ahasend messages send --sandbox --profile staging \
  --from test@staging.com \
  --to dev@example.com \
  --subject "Test" \
  --text "Testing"

# Check which profile is active
ahasend auth status
```

## Security Notes

- Credentials are stored in `~/.ahasend/config.yaml`
- File permissions are set to 600 (read/write for owner only)
- Never commit credentials to version control
- In CI, pass secrets through `--api-key "$AHASEND_API_KEY" --account-id "$AHASEND_ACCOUNT_ID"`; the CLI does not read credential environment variables automatically

## Command Flags

These flags come from the current CLI. All commands also accept the [global flags](/cli/configuration#global-flags).

### `auth login`

| Flag | Description and default |
|---|---|
| `--account-id string` | AhaSend Account ID |
| `--api-key string` | AhaSend API key (not recommended, use interactive prompt) |
| `--api-url string` | AhaSend API URL (default "https://api.ahasend.com") |
| `--profile string` | Profile name to save credentials under |

### `auth logout`

| Flag | Description and default |
|---|---|
| `--all` | Logout from all profiles |

### `auth status`

| Flag | Description and default |
|---|---|
| `--all` | Show status for all profiles |
| `--profile string` | Show status for specific profile |

### `auth switch`

This command has no command-specific flags. See [global flags](/cli/configuration#global-flags).
