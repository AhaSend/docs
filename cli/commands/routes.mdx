AhaSend CLI `routes` commands let you forward and trigger inbound email events; this page lists their arguments and flags. For the complete workflow, use the [route testing guide](/cli/route-testing).

`routes get`, `routes update`, `routes delete` and `routes trigger` take the resource ID as their positional argument. `routes create`, `routes list` and `routes listen` use the flags below. For dashboard setup, see [the routes guide](/integrations/routing).

## Command Flags

These flags come from the current CLI. All commands also accept the [global flags](/cli/configuration#global-flags).

### `routes create`

| Flag | Description and default |
|---|---|
| `--enabled` | Enable the route immediately after creation |
| `--group-by-message-id` | Group related emails by message ID (conversation threading) |
| `--include-attachments` | Include email attachments in webhook payload |
| `--include-headers` | Include email headers in webhook payload |
| `--interactive` | Use interactive mode for route configuration (default true) |
| `--name string` | Route name |
| `--recipient string` | Recipient filter pattern (e.g., 'support-*@example.com', '*@example.com'); the domain must belong to your account |
| `--strip-replies` | Strip reply content from emails |
| `--url string` | Webhook URL for processing emails |

### `routes delete`

| Flag | Description and default |
|---|---|
| `--force` | Skip confirmation prompt (for automation) |

### `routes get`

This command has no command-specific flags. See [global flags](/cli/configuration#global-flags).

### `routes list`

| Flag | Description and default |
|---|---|
| `--cursor string` | Pagination cursor for continued results |
| `--enabled` | Show only enabled routes |
| `--limit int32` | Maximum number of routes to return (default 50) |

### `routes listen`

| Flag | Description and default |
|---|---|
| `--forward-to string` | Local endpoint to forward events to |
| `--recipient string` | Recipient pattern for temporary route (e.g., *@domain.com) |
| `--route-id string` | Use existing route instead of creating temporary one |
| `--skip-verify` | Skip SSL certificate verification for local endpoints when forwarding events |
| `--slim-output` | Slim down the payload for printing to the console |

### `routes trigger`

This command has no command-specific flags. See [global flags](/cli/configuration#global-flags).

### `routes update`

| Flag | Description and default |
|---|---|
| `--clear-recipient` | Clear recipient filter (accept all emails) |
| `--disabled` | Disable the route |
| `--enabled` | Enable the route |
| `--group-by-message-id` | Enable grouping related emails by message ID |
| `--include-attachments` | Enable including attachments in webhook payload |
| `--include-headers` | Enable including headers in webhook payload |
| `--name string` | Update route name |
| `--no-group-by-message-id` | Disable grouping related emails by message ID |
| `--no-include-attachments` | Disable including attachments in webhook payload |
| `--no-include-headers` | Disable including headers in webhook payload |
| `--no-strip-replies` | Disable stripping reply content from emails |
| `--recipient string` | Update recipient filter pattern |
| `--strip-replies` | Enable stripping reply content from emails |
| `--url string` | Update webhook URL |
