Use AhaSend CLI `ping` to check your API connection and API key; this page covers its options and results.

Before running the examples, [log in](/cli/authentication), or pass an API key with the global flags: replace `YOUR_API_KEY` and `YOUR_ACCOUNT_ID` with your API key and the ID of its account.

## Overview

```text
ahasend ping [flags]
```

The `ping` command sends a ping request to the AhaSend API, which checks that:
- The API can be reached
- The API accepts the API key, from this IP address

The API answers a ping before it looks at the account. So `ping` does not check that the key belongs to the account ID, or what the key may do. Run [`ahasend auth status`](/cli/commands/auth) for that.

## Basic Usage

```bash
# Test with the default profile
ahasend ping

# Test with a specific profile
ahasend ping --profile production

# Test with an API key instead of a profile
ahasend ping --api-key YOUR_API_KEY --account-id YOUR_ACCOUNT_ID
```

## Output

Table and plain output print the API's message:

```text
pong
```

`--output json` prints the API's response body unchanged:

```json
{
  "message": "pong"
}
```

CSV output has a `message` column and one row.

## Exit Codes

`ping` uses the CLI's [exit codes](/cli/configuration#exit-codes):

- 0: The API accepts the key.
- 2: The API rejected the key.
- 6: The API refused the key with HTTP 403 because the key's IP allow list leaves out this IP address.
- 7: The API cannot be reached.

```bash
# Fail a CI job when the API or the key does not work
ahasend --api-key "$AHASEND_API_KEY" --account-id "$AHASEND_ACCOUNT_ID" ping || exit 1
```

## Command Flags

This command has no command-specific flags. It accepts the [global flags](/cli/configuration#global-flags).
