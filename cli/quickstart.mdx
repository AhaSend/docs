This guide helps you send your first email with the AhaSend CLI in a few minutes.

## Prerequisites

Before you begin, make sure you have:

1. [Installed the AhaSend CLI](/cli/installation)
2. An AhaSend account ([sign up here](https://dash.ahasend.com/user/register))
3. Your API key and Account ID from the [dashboard](https://dash.ahasend.com)
4. A domain whose DNS records you can change. The examples use `example.com`; replace it with your domain.

The examples send with `--sandbox`, so no email is delivered. [Step 4](#step-4-test-with-sandbox-mode) explains sandbox mode.

## Step 1: Authentication

First, authenticate with your AhaSend API credentials:

```bash
# Interactive login (recommended)
ahasend auth login
```

On a terminal, the command asks for:
- Your API key, hidden as you type it
- Your Account ID

The CLI checks that the key belongs to the account before it saves them. [Profiles](/cli/configuration#profiles) says which name the profile gets.

<Tip>
Your credentials are stored in `~/.ahasend/config.yaml` for future use.
</Tip>

Alternatively, provide credentials directly:

```bash
ahasend auth login --api-key YOUR_API_KEY --account-id YOUR_ACCOUNT_ID
```

Verify your authentication:

```bash
ahasend auth status
```

## Step 2: Add a Sending Domain

Before sending emails, you need to add and verify a domain:

```bash
# Add your domain
ahasend domains create example.com
```

The command prints the DNS records the domain needs, on stderr, and marks each one as required or optional. Add them to your domain's DNS settings.

After configuring your DNS records, check them:

```bash
# Check the DNS records again
ahasend domains check-dns example.com

# Show the domain and its status
ahasend domains get example.com
```

<Note>
Most records verify within minutes. DNS changes can take up to 48 hours to propagate. Run `ahasend domains check-dns` again until the DNS is valid.
</Note>

## Step 3: Send Your First Email

### Simple Text Email

```bash
ahasend messages send --sandbox \
  --from noreply@example.com \
  --to recipient@example.com \
  --subject "Hello from AhaSend CLI" \
  --text "This is my first email sent using the AhaSend CLI!"
```

### HTML Email

```bash
ahasend messages send --sandbox \
  --from noreply@example.com \
  --to recipient@example.com \
  --subject "Welcome to AhaSend" \
  --html "<h1>Welcome!</h1><p>Thank you for using AhaSend.</p>"
```

### Email with Both HTML and Text

```bash
ahasend messages send --sandbox \
  --from noreply@example.com \
  --to recipient@example.com \
  --subject "Welcome" \
  --html "<h1>Welcome to AhaSend!</h1><p>We're glad you're here.</p>" \
  --text "Welcome to AhaSend! We're glad you're here."
```

## Step 4: Test with Sandbox Mode

Before sending real emails, test your integration using sandbox mode:

```bash
ahasend messages send \
  --from noreply@example.com \
  --to test@example.com \
  --subject "Test Email" \
  --text "This is a test email in sandbox mode" \
  --sandbox
```

<Info>
Sandbox mode goes through the sending process but delivers nothing. See [sandbox behavior](/send-api/sandbox).
</Info>

You can also simulate different outcomes with `--sandbox-result`: `deliver` (the default), `bounce`, `defer`, `fail`, or `suppress`. It needs `--sandbox`.

```bash
# Simulate a bounce
ahasend messages send \
  --from noreply@example.com \
  --to test@example.com \
  --subject "Test Bounce" \
  --text "Testing bounce scenario" \
  --sandbox \
  --sandbox-result bounce

# Simulate successful delivery
ahasend messages send \
  --from noreply@example.com \
  --to test@example.com \
  --subject "Test Success" \
  --text "Testing successful delivery" \
  --sandbox \
  --sandbox-result deliver
```

## Step 5: Send Batch Emails

### Prepare Recipients File

Create a CSV file with recipient data (`recipients.csv`). The `email` and `name` columns set the recipient; each other column is a substitution:

```csv
email,name,first_name,company
john@example.com,John Doe,John,ACME Corp
jane@example.com,Jane Smith,Jane,Tech Inc
alice@example.com,Alice Johnson,Alice,StartUp Ltd
```

### Create an HTML File

Create the HTML content (`welcome.html`):

```html
<!DOCTYPE html>
<html>
<head>
    <title>Welcome {{first_name}}!</title>
</head>
<body>
    <h1>Welcome to {{company}}, {{first_name}}!</h1>
    <p>We're excited to have you on board.</p>
    <p>Best regards,<br>The AhaSend Team</p>
</body>
</html>
```

### Send Batch Emails

```bash
ahasend messages send --sandbox \
  --from welcome@example.com \
  --recipients recipients.csv \
  --subject "Welcome to {{company}}" \
  --html-file welcome.html \
  --progress \
  --show-metrics
```

The CLI:
- Sends a personalized email to each recipient
- Shows a progress bar on stderr, on a terminal only
- Prints performance metrics on stderr after the send
- Saves any failed recipients to a file in `~/.ahasend/` and prints its path, so you can pass it back to `--recipients`
- Exits with code 0 only when every recipient was sent; [exit codes](/cli/configuration#exit-codes) lists the other codes

## Step 6: Monitor Your Emails

### Check Delivery Statistics

```bash
# View statistics for the last 7 days
ahasend stats deliverability

# View statistics for a date range
ahasend stats deliverability \
  --from-time 30d \
  --to-time 7d
```

### List Recent Messages

```bash
# List recent sent messages
ahasend messages list

# Filter by status: sandbox sends have sandbox statuses
ahasend messages list --status "sandbox delivered"
```

## Common Patterns

### Using Different Output Formats

```bash
# Default plain output
ahasend domains list

# JSON format for automation: the API response, unchanged
ahasend domains list --output json

# CSV format for analysis
ahasend stats deliverability --output csv > stats.csv
```

Every failure exits with a nonzero code. [JSON output](/cli/configuration#json-output) describes what `--output json` prints, errors included, and [stdout and stderr](/cli/configuration#stdout-and-stderr) says where each part of the output goes.

### Working with Multiple Environments

```bash
# Set up different profiles
ahasend auth login --profile production
ahasend auth login --profile staging

# Use specific profile for commands
ahasend messages send --sandbox --profile staging \
  --from test@staging.example.com \
  --to dev@example.com \
  --subject "Staging Test" \
  --text "Testing staging environment"

# Switch default profile
ahasend auth switch production
```

[Profiles](/cli/configuration#profiles) says which profile is the default; `ahasend auth switch` changes it.

### Adding Attachments

```bash
ahasend messages send --sandbox \
  --from noreply@example.com \
  --to customer@example.com \
  --subject "Your Invoice" \
  --text "Please find your invoice attached." \
  --attach invoice.pdf \
  --attach receipt.pdf
```

### Scheduling Emails

`--schedule` takes a relative time, such as `2h` from now, or an RFC 3339 time. It must be in the future and at most 7 days ahead.

```bash
# Schedule for 24 hours from now
ahasend messages send --sandbox \
  --from reminder@example.com \
  --to user@example.com \
  --subject "Reminder: Meeting Tomorrow" \
  --text "Don't forget about our meeting at 2 PM." \
  --schedule 24h
```
