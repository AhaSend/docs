title: "Inbound Email Route Retry Policy"

description: "Check how AhaSend retries failed inbound email routes: attempt counts, delays, timeouts, redirect behavior, and automatic route disabling."

AhaSend makes 12 attempts over about 11 hours to deliver a route. Attempt counts include the first attempt.

Any 2xx response is successful. Any non-2xx response, timeout or connection error is a failure. Each attempt times out after 5 seconds.

The delay before each retry is (failures so far)^4 seconds, ±10%. Times in this table exclude that jitter and the time spent making requests.

| Attempt | Delay before attempt (seconds) | Total waiting time (seconds) |
|---|---|---|
| 1 | 0 | 0 |
| 2 | 1 | 1 |
| 3 | 16 | 17 |
| 4 | 81 | 98 |
| 5 | 256 | 354 |
| 6 | 625 | 979 |
| 7 | 1,296 | 2,275 |
| 8 | 2,401 | 4,676 |
| 9 | 4,096 | 8,772 |
| 10 | 6,561 | 15,333 |
| 11 | 10,000 | 25,333 |
| 12 | 14,641 | 39,974 |

After more than 100 consecutive failed attempts, the route is disabled and account users are emailed. Correct the endpoint, then [update the route](/api-reference/routes/update-route) with `enabled: true` to turn it back on.

Redirects are followed, but 301, 302 and 303 turn the POST into a GET without a body, so point the endpoint at its final URL.

Verify [signatures](/api-reference/routes/security) before processing events. Acknowledge verified unknown event types with a 2xx response so new event types do not cause repeated failures.
