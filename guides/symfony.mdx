The [`ahasend/symfony-mailer`](https://packagist.org/packages/ahasend/symfony-mailer) package brings the AhaSend bridge of Symfony 8.2, with API v2 and webhooks, to Symfony 7.4, 8.0 and 8.1. This guide installs it, sends a test email in sandbox mode, sets AhaSend options per message and receives delivery events as Symfony remote events.

On Symfony 7.4, 8.0 and 8.1, Symfony's own bridge, `symfony/aha-send-mailer`, only speaks the legacy API v1, and AhaSend no longer issues v1 API keys. Our package is that bridge from Symfony 8.2, with the same class names, service IDs and DSN, so your configuration stays the same when you move to Symfony 8.2. Its source is on [GitHub](https://github.com/AhaSend/symfony-mailer).

## Prerequisites

- Symfony 7.4, 8.0 or 8.1, with the PHP version it requires
- A [verified sending domain](/domains)
- For the API: a [send-only API key](/send-api/credentials) with the `messages:send:{your-domain}` scope, or `messages:send:all`, and your account ID
- For SMTP: an [SMTP credential](/smtp/credentials)
- For the test below, a key or credential in **Sandbox** mode, so nothing is delivered. See [sandbox mode](/send-api/sandbox).

## Install the bridge

```bash
composer require ahasend/symfony-mailer
```

The package replaces `symfony/aha-send-mailer`, so Composer removes that package if your app has it. Symfony wires the bridge as it wires its own.

## Configure the DSN

Set `MAILER_DSN` in your server's secret store, or in `.env.local` for local work. Use the API:

```dotenv .env.local
MAILER_DSN=ahasend+api://API_KEY:ACCOUNT_ID@default
```

Or SMTP:

```dotenv .env.local
MAILER_DSN=ahasend+smtp://USERNAME:PASSWORD@default
```

Replace the placeholders with your API key and account ID, or with your SMTP username and password, and URL-encode them. An `ahasend+api://` DSN without an account ID selects the legacy API v1, which only works with keys made before API v2: a v2 key (`aha-sk-...`) without an account ID is refused.

## Send a test email

From your project root, with the sandbox key or credential in `MAILER_DSN`:

```bash
php bin/console mailer:test recipient@example.com --from=hello@yourdomain.com
```

Replace `hello@yourdomain.com` with an address on your verified domain. The command exits with status 0 when AhaSend accepted the message. With a sandbox key or credential, the message shows up in your AhaSend dashboard and nothing is delivered.

In your app, inject `MailerInterface` and send an `Email` as usual. See the [Symfony Mailer documentation](https://symfony.com/doc/current/mailer.html).

## Set AhaSend options per message

Use AhaSend's [SMTP special headers](/smtp/special-headers) on the `Email`. Over SMTP, AhaSend reads them itself. On the API, the bridge moves them to the matching API fields, so the same code works with both DSNs:

```php
use Symfony\Component\Mime\Email;

$email = (new Email())
    ->from('hello@yourdomain.com')
    ->to($user->getEmail())
    ->subject('Welcome!')
    ->text('Your account is ready.');

$email->getHeaders()
    ->addTextHeader('AhaSend-Tags', 'welcome,onboarding')
    ->addTextHeader('AhaSend-Track-Opens', 'true')
    ->addTextHeader('AhaSend-Sandbox', 'true'); // validate without delivering

$mailer->send($email);
```

On the API, the bridge handles `AhaSend-Tags`, `AhaSend-Track-Opens`, `AhaSend-Track-Clicks`, `AhaSend-Sandbox`, `AhaSend-Sandbox-Result`, `AhaSend-Metadata-Retention` and `AhaSend-Data-Retention`. A malformed value throws before anything is sent, as does a retention outside the API's limits: 1 to 30 days for metadata, 0 to 30 for data.

## Recipients

On the API, a message with To addresses goes out as one message to its To, Cc and Bcc addresses, so recipients see each other and reply-all works. Bcc addresses are never shown. Each recipient gets a separate copy instead when there are more than 50 addresses, when there is no To address, or when the envelope's recipients differ from the addresses in the headers, for example with `framework.mailer.envelope.recipients`. Each copy then has its own Message-ID.

## Receive webhook events

The bridge turns AhaSend's [webhooks](/integrations/webhooks) into Symfony remote events. Install the Webhook component:

```bash
composer require symfony/webhook symfony/remote-event
```

Route AhaSend's webhooks to the bridge's request parser, with the secret of your AhaSend webhook:

```yaml config/packages/webhook.yaml
framework:
    webhook:
        routing:
            ahasend:
                service: mailer.webhook.request_parser.ahasend
                secret: '%env(AHASEND_WEBHOOK_SECRET)%'
```

Then [create a webhook](/integrations/webhooks#creating-webhooks) in AhaSend that points at `https://your-app.example/webhook/ahasend`, and set its secret in `AHASEND_WEBHOOK_SECRET`. Handle the events in a consumer:

```php src/RemoteEvent/AhaSendEventConsumer.php
<?php

namespace App\RemoteEvent;

use Symfony\Component\RemoteEvent\Attribute\AsRemoteEventConsumer;
use Symfony\Component\RemoteEvent\Consumer\ConsumerInterface;
use Symfony\Component\RemoteEvent\Event\Mailer\MailerDeliveryEvent;
use Symfony\Component\RemoteEvent\Event\Mailer\MailerEngagementEvent;
use Symfony\Component\RemoteEvent\RemoteEvent;

#[AsRemoteEventConsumer('ahasend')]
final class AhaSendEventConsumer implements ConsumerInterface
{
    public function consume(RemoteEvent $event): void
    {
        if ($event instanceof MailerDeliveryEvent) {
            // delivered, deferred, bounced, ...: $event->getName(), $event->getRecipientEmail()
        } elseif ($event instanceof MailerEngagementEvent) {
            // open, click, spam, unsubscribe
        }
    }
}
```

The ID of each event, `$event->getId()`, is the Message-ID of the email without angle brackets: the ID that `SentMessage::getMessageId()` returned when you sent it. Store it to match events with your messages. `message.complained` and `message.unsubscribed` arrive as engagement events named `spam` and `unsubscribe`. Other events, such as `suppression.created`, arrive as plain `RemoteEvent`s named after their type. To receive mail events only, turn on just the `message.*` events on the webhook.

<Note>
  In Symfony's own bridge before 8.2, the event ID was the payload's `data.id`. If you stored or compared that ID, update that code.
</Note>

## Move to Symfony 8.2

From Symfony 8.2, the official bridge has API v2. Switch back to it; your DSN and configuration stay the same:

```bash
composer remove ahasend/symfony-mailer
composer require symfony/aha-send-mailer
```
