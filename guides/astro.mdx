In Astro the send has to live in an on-demand API endpoint, since pages are prerendered by default. Switch on on-demand rendering and add the [@astrojs/node](https://docs.astro.build/en/guides/integrations-guide/node/) adapter to get real server endpoints.

## Prerequisites

- An Astro 4 or 5 project on Node.js 22 or later
- An [AhaSend account](https://dash.ahasend.com/user/register) with a verified sending domain
- An [API key](https://dash.ahasend.com/account/-/settings/api-keys) with the `messages:send:all` scope, and your account ID

## Install the SDK and the Node Adapter

<CodeGroup>

```bash npm
npm install @ahasend/sdk
npx astro add node
```

```bash pnpm
pnpm add @ahasend/sdk
pnpm astro add node
```

```bash yarn
yarn add @ahasend/sdk
yarn astro add node
```

```bash bun
bun add @ahasend/sdk
bunx astro add node
```

</CodeGroup>

`astro add node` wires the adapter into `astro.config.mjs` for you:

```js astro.config.mjs
import { defineConfig } from "astro/config";
import node from "@astrojs/node";

export default defineConfig({
 adapter: node({ mode: "standalone" }),
});
```

<Note>
  Use the Node adapter, or another Node-compatible host such as Bun. Edge adapters (Cloudflare, Vercel Edge) cannot run the SDK: see the [Cloudflare Workers guide](/guides/cloudflare-workers) for those.
</Note>

## Configure Environment Variables

```bash .env
AHASEND_API_KEY=aha-sk-...
AHASEND_ACCOUNT_ID=your-account-uuid
AHASEND_WEBHOOK_SECRET=aha-whsec-...
```

Server-side code reads these via `import.meta.env`.

<Warning>
In Astro, only env vars prefixed with `PUBLIC_` are exposed to client-side code, so never name it `PUBLIC_AHASEND_API_KEY`, or the key ships in your client bundle to every visitor. Unprefixed variables like `AHASEND_API_KEY` stay server-only.
</Warning>

## Create the Client

Create the client once at module scope and reuse it across requests:

```ts src/lib/ahasend.ts
import { AhaSendClient } from "@ahasend/sdk";

export const ahasend = new AhaSendClient({
 apiKey: import.meta.env.AHASEND_API_KEY,
 accountId: import.meta.env.AHASEND_ACCOUNT_ID,
});
```

## Send an Email from an Astro API Endpoint

API routes live under `src/pages/api/`. Mark the route `prerender = false` so it renders on demand instead of being built as a static file (required in static-first projects; harmless if your whole site is already `output: "server"`):

```ts src/pages/api/welcome.ts
import type { APIRoute } from "astro";
import { AhaSendAPIError } from "@ahasend/sdk";
import { ahasend } from "../../lib/ahasend";

export const prerender = false;

export const POST: APIRoute = async ({ request }) => {
 const { email, name } = await request.json();

 try {
 const result = await ahasend.messages.send({
 from: { email: "hello@yourdomain.com", name: "Your App" },
 recipients: [{ email, name }],
 subject: "Welcome to Your App!",
 html_content: "<h1>Welcome aboard 🎉</h1><p>We're glad you're here.</p>",
 text_content: "Welcome aboard! We're glad you're here.",
 });

 const rejected = result.data.filter((r) => r.status === "error");
 if (rejected.length > 0) console.warn(`${rejected.length} recipient(s) rejected`);

 return Response.json({ statuses: result.data.map((r) => r.status) }); // ["queued"]
 } catch (err) {
 if (err instanceof AhaSendAPIError) {
 console.error(`AhaSend error ${err.status} (request ${err.requestId})`, err.body);
 return Response.json({ error: "Failed to send email" }, { status: 502 });
 }
 throw err;
 }
};
```

A 202 is **multi-status**: `result.data` carries one entry per recipient, and an individual recipient can come back `status: "error"` with a null `id` (a suppressed address, say) while the call itself succeeds, so check every entry, not just the first.

The SDK retries transient failures automatically, but a retry after a 5xx can still send twice, so pass your own `idempotencyKey` when a duplicate would be expensive.

Add `sandbox: true` to the send request to validate it without delivering anything.

## Handle Webhooks

Astro endpoints receive a standard `Request`, so `verifier.parse()` takes `request.headers` and the raw body from `request.text()` directly, no adapter needed. Read the body as text, not JSON, so the verifier sees the exact bytes AhaSend signed.

```ts src/pages/api/webhooks/ahasend.ts
import type { APIRoute } from "astro";
import { WebhookVerifier, isKnownWebhookEvent } from "@ahasend/sdk/webhooks";

export const prerender = false;

const verifier = new WebhookVerifier(import.meta.env.AHASEND_WEBHOOK_SECRET);

export const POST: APIRoute = async ({ request }) => {
 let event;
 try {
 event = verifier.parse(request.headers, await request.text());
 } catch {
 return new Response("Invalid signature", { status: 400 });
 }

 if (isKnownWebhookEvent(event)) {
 switch (event.type) {
 case "message.delivered":
 console.log(`Delivered to ${event.data.recipient}`);
 break;
 case "message.bounced":
 console.log(`Bounced: ${event.data.recipient}`);
 break;
 case "message.opened":
 console.log(`Opened by ${event.data.recipient}`);
 break;
 }
 }

 return new Response(null, { status: 200 });
};
```

Create the webhook in your [AhaSend dashboard](https://dash.ahasend.com) pointing at `https://your-app.com/api/webhooks/ahasend`, and copy its secret into `AHASEND_WEBHOOK_SECRET` exactly as shown (including the `aha-whsec-` prefix).

## Going Further

- **Templating**: pass `substitutions` per recipient and use `{{ variable }}` in the subject or body.
- **Batch sends**: `recipients` accepts up to 100 entries; each gets a separate, individually-substituted message.
- **Scheduling**: set `schedule: { first_attempt: "2026-07-04T09:00:00Z" }` to defer delivery.
- **Attachments**: pass `attachments: [{ data, content_type, file_name, base64: true }]`. Set `base64: true` for binary files such as PDFs.

See the [API reference](https://ahasend.com/docs/api-reference) for every endpoint the SDK exposes. Using a different meta-framework? The same SDK powers the [Next.js](/guides/nextjs) and [SvelteKit](/guides/sveltekit) guides.

## Troubleshooting

<AccordionGroup>
 <Accordion title="POST returns 404 or a static HTML page">
 The route was prerendered at build time. Add `export const prerender = false` to the endpoint (or set `output: "server"` globally) and make sure an adapter is configured. On-demand endpoints don't work with a purely static build.
 </Accordion>
 <Accordion title="import.meta.env.AHASEND_API_KEY is undefined">
 Unprefixed variables are only available server-side, so check you're not reading it inside a client component or a `<script>` tag. Also note Astro loads `.env` from the project root; production hosts need the variables set in their own dashboard.
 </Accordion>
 <Accordion title="Webhook verification fails with 400">
 Pass `await request.text()` to `verifier.parse()`, not a re-serialized `JSON.stringify(await request.json())`: re-serialization changes byte layout, so the signature no longer matches.
 </Accordion>
 <Accordion title="400 error mentioning the from address">
 The `from` address must belong to a verified sending domain on your account. Check domain status in the dashboard.
 </Accordion>
</AccordionGroup>
