Read the key from [SvelteKit](https://svelte.dev/docs/kit)'s `$env/dynamic/private`, never the `PUBLIC_` variants, and a leaked key becomes a build error instead of a production incident.

## Prerequisites

- Node.js 22 or later and a SvelteKit 2 project
- An [AhaSend account](https://dash.ahasend.com/user/register) with a verified sending domain
- An [API key](https://dash.ahasend.com/account/-/settings/api-keys) with the `messages:send:all` scope, and your account ID

## Configure Environment Variables

Add your credentials to `.env`, which SvelteKit (via Vite) loads automatically in development:

```bash .env
AHASEND_API_KEY=aha-sk-...
AHASEND_ACCOUNT_ID=your-account-uuid
AHASEND_WEBHOOK_SECRET=aha-whsec-...
```

Read secrets from a **private** env module. Both work:

- `$env/dynamic/private`: read at runtime from `process.env`, for deployments that inject variables at start-up.
- `$env/static/private`: inlined at build time, and the build fails if a variable is missing.

## Create the Client

Create the client once at module scope and reuse it across requests. SvelteKit refuses to bundle `$lib/server/` modules into client code, so keep it there:

```ts src/lib/server/ahasend.ts
import { env } from "$env/dynamic/private";
import { AhaSendClient } from "@ahasend/sdk";

export const ahasend = new AhaSendClient({
 apiKey: env.AHASEND_API_KEY!,
 accountId: env.AHASEND_ACCOUNT_ID!,
});
```

## Send an Email from a SvelteKit Endpoint

```ts src/routes/api/welcome/+server.ts
import { json } from "@sveltejs/kit";
import type { RequestHandler } from "./$types";
import { AhaSendAPIError } from "@ahasend/sdk";
import { ahasend } from "$lib/server/ahasend";

export const POST: RequestHandler = async ({ request }) => {
 const { email, name } = await request.json();

 try {
 const result = await ahasend.messages.send({
 from: { email: "hello@yourdomain.com", name: "Your App" },
 recipients: [{ email, name }],
 subject: "Welcome to Your App!",
 html_content: "<h1>Welcome aboard 🎉</h1><p>We're glad you're here.</p>",
 text_content: "Welcome aboard! We're glad you're here.",
 });

 const rejected = result.data.filter((r) => r.status === "error");
 return json({ queued: result.data.length - rejected.length, rejected });
 } catch (err) {
 if (err instanceof AhaSendAPIError) {
 console.error(`AhaSend error ${err.status} (request ${err.requestId})`, err.body);
 return json({ error: "Failed to send email" }, { status: 502 });
 }
 throw err;
 }
};
```

A 202 is a **multi-status** response: `result.data` holds one entry per recipient, and an individual recipient can come back with `status: "error"` and a null `id` (a suppressed address, for example) while the call itself succeeds. Inspect every entry, not just the first.

The SDK retries transient failures automatically, but a retry after a 5xx can still send twice, so pass your own `idempotencyKey` when a duplicate would be expensive. Form actions in `+page.server.ts` can call `ahasend.messages.send()` the same way.

Add `sandbox: true` to the send request to validate it without delivering anything.

## Handle Webhooks

Signature verification needs the raw body, so read it with `request.text()` and pass it to `verifier.parse()` together with the request headers; the verifier accepts a Fetch `Headers` object directly:

```ts src/routes/api/webhooks/ahasend/+server.ts
import type { RequestHandler } from "./$types";
import { env } from "$env/dynamic/private";
import { WebhookVerifier, isKnownWebhookEvent } from "@ahasend/sdk/webhooks";

let verifier: WebhookVerifier | undefined;

export const POST: RequestHandler = async ({ request }) => {
 verifier ??= new WebhookVerifier(env.AHASEND_WEBHOOK_SECRET!);

 let event;
 try {
 event = verifier.parse(request.headers, await request.text());
 } catch {
 return new Response(null, { status: 400 });
 }

 if (isKnownWebhookEvent(event)) {
 switch (event.type) {
 case "message.delivered":
 console.log(`Delivered to ${event.data.recipient}`);
 break;
 case "message.bounced":
 console.log(`Bounced: ${event.data.recipient}`);
 break;
 case "message.opened":
 console.log(`Opened by ${event.data.recipient}`);
 break;
 }
 }

 return new Response(null, { status: 200 });
};
```

Create the webhook in your [AhaSend dashboard](https://dash.ahasend.com) pointing at `https://your-app.com/api/webhooks/ahasend`, and copy its secret into `AHASEND_WEBHOOK_SECRET` exactly as shown (including the `aha-whsec-` prefix).

## Going Further

- **Deployment**: use `@sveltejs/adapter-node` or a Node serverless target. Edge adapters cannot run the SDK.
- **Templating**: pass `substitutions` per recipient and use `{{ variable }}` in the subject or body.
- **Batch sends**: `recipients` accepts up to 100 entries; each gets a separate, individually-substituted message.
- **Scheduling**: set `schedule: { first_attempt: "2026-07-04T09:00:00Z" }` to defer delivery.
- **Attachments**: pass `attachments: [{ data, content_type, file_name, base64: true }]`. Set `base64: true` for binary files such as PDFs.

See the [API reference](https://ahasend.com/docs/api-reference) for every endpoint the SDK exposes. The same server-side pattern works in the other meta-frameworks: see the [Next.js](/guides/nextjs) and [Nuxt](/guides/nuxt) guides.

## Troubleshooting

<AccordionGroup>
 <Accordion title="Cannot import $env/static/private into client-side code">
 You imported the AhaSend client (or an env module) from a component or `+page.ts` that runs in the browser. Move all SDK usage into `+server.ts`, `+page.server.ts`, or `$lib/server/` modules: SvelteKit enforces this boundary for you.
 </Accordion>
 <Accordion title="API key visible in the browser bundle">
 The variable was prefixed with `PUBLIC_` and imported via a public env module. Rename it to `AHASEND_API_KEY`, rotate the leaked key in the dashboard, and read it only from `$env/dynamic/private` or `$env/static/private`.
 </Accordion>
 <Accordion title="Error about window/document or node:crypto on deploy">
 Your adapter targets an edge runtime the SDK cannot run on. Switch to `@sveltejs/adapter-node` (or your host's Node functions runtime), or send via the REST API from edge code.
 </Accordion>
 <Accordion title="401 AhaSendAuthenticationError">
 The API key is missing, malformed, or revoked. With `$env/static/private` a missing variable fails the build; with `$env/dynamic/private` it fails at request time. Confirm the variable is set in your production environment and that the key exists in your [dashboard](https://dash.ahasend.com/account/-/settings/api-keys).
 </Accordion>
</AccordionGroup>
