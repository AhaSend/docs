In [RedwoodJS](https://redwoodjs.com) the SDK belongs in the `api` workspace only, so the key never reaches anything the browser downloads. The send goes in a service, the webhook is just another api-side function.

## Prerequisites

- A RedwoodJS project
- An [AhaSend account](https://dash.ahasend.com/user/register) with a verified sending domain
- An [API key](https://dash.ahasend.com/account/-/settings/api-keys) with the `messages:send:all` scope, and your account ID

## Install the SDK

The SDK belongs on the **api side** only, so install it into the `api` workspace:

<CodeGroup>

```bash yarn (Redwood default)
yarn workspace api add @ahasend/sdk
```

```bash npm
npm install @ahasend/sdk --workspace api
```

```bash pnpm
pnpm add @ahasend/sdk --filter api
```

```bash bun
bun add @ahasend/sdk --cwd api
```

</CodeGroup>

## Configure Environment Variables

Add your credentials to the project's `.env` for local development. The api side reads `process.env` directly:

```bash .env
AHASEND_API_KEY=aha-sk-...
AHASEND_ACCOUNT_ID=your-account-uuid
AHASEND_WEBHOOK_SECRET=aha-whsec-...
WELCOME_ROUTE_TOKEN=replace-with-a-long-random-value
```

<Warning>
  Redwood's `includeEnvironmentVariables` setting in `redwood.toml` allowlists variables for the **web side**, baking them into the browser bundle. Never add any `AHASEND_*` variable or `WELCOME_ROUTE_TOKEN` there: the api side needs no allowlist and these secrets must stay server-only.
</Warning>

## Create the Client

Create the client once at module scope and reuse it across invocations:

```ts api/src/lib/ahasend.ts
import { AhaSendClient } from "@ahasend/sdk";

export const ahasend = new AhaSendClient({
  apiKey: requireEnv("AHASEND_API_KEY"),
  accountId: requireEnv("AHASEND_ACCOUNT_ID"),
});

export function requireEnv(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`${name} is not configured`);
  return value;
}
```

Configure the same values as runtime environment variables in your deployment provider. Do not commit `.env`.

## Send an Email from a Redwood Serverless Function

A Redwood function gives you an HTTP endpoint at `/.redwood/functions/sendWelcome` through the default web-side API proxy, or `/sendWelcome` on the api server during development. The deployed path follows the `apiUrl` configured for your target.

```ts api/src/functions/sendWelcome.ts
import { createHash, timingSafeEqual } from "node:crypto";
import type { APIGatewayEvent, APIGatewayProxyResult } from "aws-lambda";
import { isAhaSendError } from "@ahasend/sdk";
import { ahasend, requireEnv } from "src/lib/ahasend";

type WelcomeRequest = { email: string; name?: string; eventId: string };

function response(statusCode: number, body: object): APIGatewayProxyResult {
  return {
    statusCode,
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body),
  };
}

function getHeader(event: APIGatewayEvent, name: string): string {
  const entry = Object.entries(event.headers).find(
    ([key]) => key.toLowerCase() === name.toLowerCase(),
  );
  return entry?.[1] ?? "";
}

function isAuthorized(event: APIGatewayEvent): boolean {
  const authorization = getHeader(event, "authorization");
  const supplied = authorization.startsWith("Bearer ") ? authorization.slice(7) : "";
  const digest = (value: string) => createHash("sha256").update(value).digest();
  return timingSafeEqual(digest(supplied), digest(requireEnv("WELCOME_ROUTE_TOKEN")));
}

function isWelcomeRequest(value: unknown): value is WelcomeRequest {
  if (typeof value !== "object" || value === null) return false;
  const body = value as Record<string, unknown>;
  return (
    typeof body.email === "string" &&
    body.email.length <= 320 &&
    /^[^\s@]+@[^\s@]+$/.test(body.email) &&
    (body.name === undefined ||
      (typeof body.name === "string" && body.name.length > 0 && body.name.length <= 100)) &&
    typeof body.eventId === "string" &&
    /^[A-Za-z0-9._:-]{1,200}$/.test(body.eventId)
  );
}

export const handler = async (event: APIGatewayEvent): Promise<APIGatewayProxyResult> => {
  if (event.httpMethod !== "POST") {
    return {
      ...response(405, { error: "Method not allowed" }),
      headers: { "Content-Type": "application/json", Allow: "POST" },
    };
  }
  if (!isAuthorized(event)) return response(401, { error: "Unauthorized" });
  if (!/^application\/json(?:\s*;|$)/i.test(getHeader(event, "content-type"))) {
    return response(415, { error: "Expected application/json" });
  }

  const bodyBytes = event.isBase64Encoded
    ? Buffer.from(event.body ?? "", "base64")
    : Buffer.from(event.body ?? "", "utf8");
  if (bodyBytes.byteLength > 16_384) {
    return response(413, { error: "Request body too large" });
  }

  let input: unknown;
  try {
    input = JSON.parse(bodyBytes.toString("utf8"));
  } catch {
    return response(400, { error: "Invalid JSON" });
  }
  if (!isWelcomeRequest(input)) return response(400, { error: "Invalid request" });

  let result;
  try {
    result = await ahasend.messages.send(
      {
        from: { email: "hello@yourdomain.com", name: "Your App" },
        recipients: [{ email: input.email, name: input.name }],
        subject: "Welcome to Your App!",
        html_content: "<h1>Welcome aboard 🎉</h1><p>We're glad you're here.</p>",
        text_content: "Welcome aboard! We're glad you're here.",
      },
      { idempotencyKey: `welcome:${input.eventId}` },
    );
  } catch (err) {
    if (isAhaSendError(err)) {
      const { code, status, requestId } = err.toJSON();
      console.error("AhaSend request failed", { code, status, requestId });
      return response(502, { error: "Failed to send email" });
    }
    throw err;
  }

  if (result.data.some((entry) => entry.status === "error")) {
    return response(502, { error: "Failed to queue email" });
  }
  return response(202, { queued: true });
};
```

A 202 from AhaSend is a **multi-status** response: `result.data` holds one entry per recipient, and an individual recipient can come back with `status: "error"` and a null `id` while the call itself succeeds. Inspect every entry, but do not return recipient-level errors because they can contain addresses and provider diagnostics.

Redwood functions are public endpoints unless you secure them. This example is for calls from another trusted server using a high-entropy bearer token. For calls from your web side, prefer Redwood authentication or an authenticated GraphQL mutation, and derive the recipient from the verified user instead of trusting a submitted address. Apply rate limiting at the deployment layer.

`eventId` must be a stable ID for the welcome-email business event, persisted by the caller and reused for every retry. The SDK reuses the explicit idempotency key during its retries; a 5xx can be re-executed, so reconcile an uncertain result instead of inventing a new event ID.

### Alternative: Send from a Service

If sending belongs to your GraphQL flow (say, after `createUser`), put the send in a service and call it from a mutation resolver: services are plain server-side functions, so the same client works:

```ts api/src/services/emails/emails.ts
import { isAhaSendError } from "@ahasend/sdk";
import { ahasend } from "src/lib/ahasend";

export const sendWelcomeEmail = async ({
  email,
  name,
  eventId,
}: {
  email: string;
  name?: string;
  eventId: string;
}) => {
  let result;
  try {
    result = await ahasend.messages.send(
      {
        from: { email: "hello@yourdomain.com", name: "Your App" },
        recipients: [{ email, name }],
        subject: "Welcome to Your App!",
        text_content: "Welcome aboard! We're glad you're here.",
      },
      { idempotencyKey: `welcome:${eventId}` },
    );
  } catch (error) {
    if (isAhaSendError(error)) throw new Error("AhaSend request failed");
    throw error;
  }
  if (result.data.some((entry) => entry.status === "error")) {
    throw new Error("Failed to queue welcome email");
  }
  return { queued: true };
};
```

Protect the mutation with your normal Redwood auth directive, validate its input, derive `email` from the authenticated user where possible, and use a persisted business-event ID for `eventId`.

Add `sandbox: true` to the send request to validate it without delivering anything.

## Handle Webhooks

Redwood functions use the Lambda-style event. Preserve its body as bytes, decoding it first when the adapter marks it as base64-encoded, then await verification before processing anything as trusted:

```ts api/src/functions/ahasendWebhook.ts
import type { APIGatewayEvent } from "aws-lambda";
import {
  AhaSendWebhookVerificationError,
  WebhookVerifier,
  isKnownWebhookEvent,
} from "@ahasend/sdk/webhooks";
import { requireEnv } from "src/lib/ahasend";

const verifier = new WebhookVerifier(requireEnv("AHASEND_WEBHOOK_SECRET"));
const MAX_WEBHOOK_BYTES = 1_000_000;

export const handler = async (event: APIGatewayEvent) => {
  if (event.httpMethod !== "POST") {
    return { statusCode: 405, headers: { Allow: "POST" }, body: "" };
  }

  const rawBody = event.isBase64Encoded
    ? Buffer.from(event.body ?? "", "base64")
    : Buffer.from(event.body ?? "", "utf8");
  if (rawBody.byteLength > MAX_WEBHOOK_BYTES) {
    return { statusCode: 413, body: "" };
  }

  let webhookEvent;
  try {
    webhookEvent = await verifier.parse(event.headers, rawBody);
  } catch (error) {
    if (error instanceof AhaSendWebhookVerificationError) {
      return { statusCode: 400, body: "" };
    }
    throw error;
  }

  if (isKnownWebhookEvent(webhookEvent)) {
    // Atomically deduplicate webhook-id and enqueue durable work here.
    // Do not log the event or recipient data.
    console.log("Verified AhaSend webhook", { type: webhookEvent.type });
  }

  return { statusCode: 200, body: "" };
};
```

Create the webhook in your [AhaSend dashboard](https://dash.ahasend.com) using the public `apiUrl` for your deployed function, followed by `/ahasendWebhook`. With Redwood's default proxy path that is `https://your-app.com/.redwood/functions/ahasendWebhook`, but deployment setup can change it. Copy the secret into `AHASEND_WEBHOOK_SECRET` exactly as shown, including the `aha-whsec-` prefix.

Signature timestamp checks do not prevent replay inside the accepted window. Before adding side effects, atomically store the `webhook-id` header with a unique constraint together with a durable work/outbox record. On a uniqueness conflict, return success without enqueuing the work again. Process the durable work idempotently, acknowledge unknown event types, and return quickly so completed work is not retried.

## Going Further

- **Templating**: pass `substitutions` per recipient and use `{{ variable }}` in the subject or body.
- **Batch sends**: `recipients` accepts up to 100 entries; each gets a separate, individually-substituted message.
- **Scheduling**: set `schedule: { first_attempt: new Date(Date.now() + 60_000).toISOString() }` to defer delivery.
- **Your own idempotency keys**: pass a stable business-event key, such as `{ idempotencyKey: "order:<order-id>" }`, as the second argument to `send()`.
- **Attachments**: pass `attachments: [{ data, content_type, file_name, base64: true }]`. Set `base64: true` for binary files such as PDFs.

See the [API reference](https://ahasend.com/docs/api-reference) for every endpoint the SDK exposes. Redwood functions use the Lambda event shape, so the [AWS Lambda guide](/guides/aws-lambda) applies almost verbatim when you deploy there; for a plain Node server instead, see the [Express guide](/guides/express).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Webhook verification always returns 400">
    Confirm that base64-marked bodies are decoded to bytes exactly once, no middleware parsed or rewrote the body, and `AHASEND_WEBHOOK_SECRET` matches this dashboard endpoint including the `aha-whsec-` prefix.
  </Accordion>
  <Accordion title="401 AhaSendAuthenticationError">
    The API key is missing, malformed, or revoked. Verify `AHASEND_API_KEY` is in `.env` (restart `yarn rw dev` after editing it) or set in your deploy provider's environment, and that the key exists in your [dashboard](https://dash.ahasend.com/account/-/settings/api-keys).
  </Accordion>
  <Accordion title="Variable undefined on the web side">
    That's by design. Do not add `AHASEND_*` keys or `WELCOME_ROUTE_TOKEN` to `includeEnvironmentVariables`, which would embed them in the browser bundle. Email must always go through the api side (a function or service).
  </Accordion>
  <Accordion title="400 error mentioning the from address">
    The `from` address must belong to a verified sending domain on your account. Check domain status in the dashboard.
  </Accordion>
</AccordionGroup>
