[`@ahasend/sdk`](https://www.npmjs.com/package/@ahasend/sdk) is the official Node.js and TypeScript SDK for AhaSend. Typed models, retries that carry an idempotency key, and a separate webhooks entry point that verifies signatures for you.

This page is the SDK reference. To wire it into a specific framework, pick a guide from the sidebar.

## Install

<CodeGroup>

```bash npm
npm install @ahasend/sdk
```

```bash pnpm
pnpm add @ahasend/sdk
```

```bash yarn
yarn add @ahasend/sdk
```

```bash bun
bun add @ahasend/sdk
```

</CodeGroup>

Node.js 22 or later. TypeScript declarations ship with the package, so there is no `@types` to add. Your `tsconfig.json` needs `moduleResolution` set to `Bundler`, `Node16`, or `NodeNext`, and either `"lib": ["DOM"]` or `@types/node` for the `fetch`, `Request`, `Response`, and `AbortSignal` globals.

<Note>
  The SDK needs `node:crypto` and `node:buffer`, so the constructor throws in browsers, service workers, and edge runtimes including Cloudflare Workers, Vercel Edge, and Supabase Edge Functions. On those, call the [REST API](/api-reference) with `fetch`. The [Cloudflare Workers guide](/guides/cloudflare-workers) has the full pattern, webhook verification included.
</Note>

## Send Your First Email

```js send.mjs
import { AhaSendClient } from "@ahasend/sdk";

const ahasend = new AhaSendClient({
  apiKey: process.env.AHASEND_API_KEY,
  accountId: process.env.AHASEND_ACCOUNT_ID,
});

const result = await ahasend.messages.send({
  from: { email: "hello@yourdomain.com", name: "Your App" },
  recipients: [{ email: "user@example.com", name: "Jane" }],
  subject: "Welcome to Your App",
  html_content: "<h1>Welcome aboard</h1>",
  text_content: "Welcome aboard",
  sandbox: true, // validates and queues without delivering
});

const rejected = result.data.filter((r) => r.status === "error");
console.log(`${result.data.length - rejected.length} queued, ${rejected.length} rejected`);
```

Run it with `node --env-file=.env send.mjs`. Drop `sandbox` when you want mail to actually leave.

Note what the last two lines are doing. `recipients` takes up to 100 addresses and each one becomes its own message, so `result.data` holds one entry per recipient. A single recipient can come back `status: "error"` with a null `id`, a suppressed address for instance, while the call itself succeeds. Reading `data[0]` would miss that.

Body fields are snake_case, matching the API. Beyond the ones above: `reply_to`, `attachments`, `headers`, `substitutions`, `tags`, `tracking`, `retention`, and `schedule`. For one message with visible To, Cc, and Bcc recipients, use `messages.sendConversation()` instead.

<Tip>
  `sandbox_result` rehearses a specific outcome: `deliver`, `bounce`, `defer`, `fail`, or `suppress`. Each one fires the matching webhook, so you can test your bounce handling without a real bounce. See [Sandbox Mode](/send-api/sandbox).
</Tip>

## Configure the Client

Build the client once at module scope and share it. It holds connection pooling, retry, and idempotency state, so one per request throws that away.

```ts lib/ahasend.ts
import { AhaSendClient } from "@ahasend/sdk";

export const ahasend = new AhaSendClient({
  apiKey: process.env.AHASEND_API_KEY!,
  accountId: process.env.AHASEND_ACCOUNT_ID!,
});
```

`AhaSendClient.fromEnv()` builds the same client from `AHASEND_API_KEY` (or `AHASEND_TOKEN`) and `AHASEND_ACCOUNT_ID`, along with the other `AHASEND_*` variables.

| Option | Default | Purpose |
| --- | --- | --- |
| `apiKey` | required | Your API key |
| `accountId` | required | Account UUID, one client per account |
| `baseUrl` | `https://api.ahasend.com` | HTTPS enforced, localhost exempted |
| `timeoutMs` | `30_000` | Per-attempt timeout in milliseconds |
| `retry` | enabled, 3 retries | Exponential backoff with jitter |
| `rateLimit` | disabled | Opt-in local request pacing |
| `idempotency` | auto-generate | Idempotency key behaviour on create operations |
| `fetch` | `globalThis.fetch` | Inject your own fetch implementation |
| `hooks` | none | `onRequest`, `onResponse`, `onRetry`, `onError` telemetry |
| `debug` | `false` | Console diagnostics |

Every method also takes a trailing options object:

```ts
await ahasend.messages.send(body, {
  idempotencyKey: `order-${orderId}`, // drive the key from your own identifier
  timeoutMs: 5_000, // override the per-attempt timeout
  retry: { maxRetries: 1 }, // restrict retries, or false to disable
  signal: AbortSignal.timeout(10_000), // cancel the request
  headers: { "x-trace-id": traceId },
});
```

## Errors

Every non-2xx response throws a typed error:

```ts
import { AhaSendAPIError, AhaSendRateLimitError } from "@ahasend/sdk";

try {
  await ahasend.messages.send(body);
} catch (err) {
  if (err instanceof AhaSendRateLimitError) {
    console.warn(`Rate limited, retry after ${err.retryAfterSeconds}s`);
  } else if (err instanceof AhaSendAPIError) {
    console.error(`AhaSend error ${err.status} (request ${err.requestId})`);
  } else {
    throw err;
  }
}
```

`AhaSendError` is the root. `AhaSendAPIError` carries `.status`, `.code`, `.requestId`, and `.body`, and branches into `AhaSendBadRequestError`, `AhaSendAuthenticationError`, `AhaSendPermissionError`, `AhaSendNotFoundError`, `AhaSendConflictError`, `AhaSendUnprocessableEntityError`, `AhaSendRateLimitError`, and `AhaSendServerError`. Alongside it sit `AhaSendConnectionError` with its `AhaSendTimeoutError` subclass, plus `AhaSendAbortError`, `AhaSendConfigurationError`, and `AhaSendResponseParseError`.

Match on `error.code` or `error.status`, never on message text: `error.message` is derived and capped at 200 characters.

## Retries and Idempotency

The SDK retries `408`, `429`, `5xx`, network failures, and timeouts with exponential backoff, and never retries other `4xx` responses. It attaches a UUID `Idempotency-Key` to every create operation and reuses that key across its own retries.

<Note>
  Stored outcomes replay for 24 hours, covering 2xx and deterministic 4xx responses. Server errors are not stored, so a retry after a 5xx can still result in a second send. Pass your own `idempotencyKey` derived from a stable business identifier when a duplicate would be expensive.
</Note>

Local rate pacing is separate and off by default. Turn it on with `rateLimit: { enabled: true }`.

```ts
for await (const message of ahasend.messages.iterate({ status: "Delivered" })) {
  // pages are fetched as needed
}
```

## Webhooks

`@ahasend/sdk/webhooks` is a separate entry point holding the Standard Webhooks HMAC-SHA256 verifier, typed parsers for all 11 event types, and adapters for Express, Fastify, and Next.js. It does not pull in the API client.

```ts
import { WebhookVerifier, isKnownWebhookEvent } from "@ahasend/sdk/webhooks";

const verifier = new WebhookVerifier(process.env.AHASEND_WEBHOOK_SECRET!);
const event = verifier.parse(request.headers, rawBody);

if (isKnownWebhookEvent(event)) {
  switch (event.type) {
    case "message.delivered":
      break;
    case "message.bounced":
      break;
  }
}
```

<Warning>
  Verification needs the **raw request body**, the exact bytes AhaSend sent. If a JSON body parser runs first the signature can no longer be checked, and the adapters treat that as a setup error. Pass the webhook secret exactly as the dashboard shows it, `aha-whsec-` prefix included.
</Warning>

Timestamp checking rejects stale deliveries, but it does not deduplicate a valid one replayed inside the window. Commit each `webhook-id` durably and make your side effects idempotent.
