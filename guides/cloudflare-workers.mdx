The SDK runs on workerd natively, with no `nodejs_compat` flag, so a Worker gets the same typed client, retries and webhook verifier as a Node server.

<Note>
  Edge runtime support landed in `@ahasend/sdk` 0.2.0. On 0.1.0 the constructor refuses to run on Workers, so upgrade before following this guide.
</Note>

## Prerequisites

- A Workers project set up with [Wrangler](https://developers.cloudflare.com/workers/wrangler/)
- An [AhaSend account](https://dash.ahasend.com/user/register) with a verified sending domain
- An [API key](https://dash.ahasend.com/account/-/settings/api-keys) with the `messages:send:all` scope, and your account ID

If you're starting from scratch:

## Configure Secrets

Store credentials as Worker secrets, never in the `wrangler.toml` `vars` block, which ends up in source control:

```bash
wrangler secret put AHASEND_API_KEY
wrangler secret put AHASEND_ACCOUNT_ID
wrangler secret put AHASEND_WEBHOOK_SECRET
```

For local development, put the same values in a `.dev.vars` file, which is git-ignored by default. Type the bindings in your Worker:

```ts src/index.ts
export interface Env {
  AHASEND_API_KEY: string;
  AHASEND_ACCOUNT_ID: string;
  AHASEND_WEBHOOK_SECRET: string;
}
```

## Send an Email from a Worker

Workers have no `process.env`, so secrets arrive on the `env` argument and the client is built per request rather than at module scope:

```ts src/index.ts
import { AhaSendClient, AhaSendAPIError } from "@ahasend/sdk";

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (request.method === "POST" && url.pathname === "/api/welcome") {
      const { email, name } = await request.json<{ email: string; name?: string }>();

      const ahasend = new AhaSendClient({
        apiKey: env.AHASEND_API_KEY,
        accountId: env.AHASEND_ACCOUNT_ID,
      });

      try {
        const result = await ahasend.messages.send({
          from: { email: "hello@yourdomain.com", name: "Your App" },
          recipients: [{ email, name }],
          subject: "Welcome to Your App",
          html_content: "<h1>Welcome aboard</h1><p>We're glad you're here.</p>",
          text_content: "Welcome aboard. We're glad you're here.",
        });

        const rejected = result.data.filter((r) => r.status === "error");
        if (rejected.length > 0) console.warn(`${rejected.length} recipient(s) rejected`);

        return Response.json({ statuses: result.data.map((r) => r.status) });
      } catch (err) {
        if (err instanceof AhaSendAPIError) {
          console.error(`AhaSend error ${err.status} (request ${err.requestId})`);
          return Response.json({ error: "Failed to send email" }, { status: 502 });
        }
        throw err;
      }
    }

    return new Response("Not found", { status: 404 });
  },
};
```

A 202 is **multi-status**: `result.data` carries one entry per recipient, and an individual recipient can come back `status: "error"` with a null `id` (a suppressed address, say) while the call itself succeeds, so check every entry, not just the first.

Add `sandbox: true` to the send request to validate it without delivering anything.

<Warning>
  Isolates are reused across requests, so never cache the client in a module-scope variable keyed to one request's `env`. Constructing it inside `fetch` is cheap and keeps each request's credentials scoped to that request.
</Warning>

## Handle Webhooks

The webhooks subpath verifies signatures with Web Crypto, which workerd provides natively. Read the body with `request.text()`, not `request.json()`, so the verifier sees the exact bytes AhaSend signed:

```ts src/index.ts
import { WebhookVerifier, isKnownWebhookEvent } from "@ahasend/sdk/webhooks";

// inside the fetch handler:
if (request.method === "POST" && url.pathname === "/webhooks/ahasend") {
  const verifier = new WebhookVerifier(env.AHASEND_WEBHOOK_SECRET);

  let event;
  try {
    event = await verifier.parse(request.headers, await request.text());
  } catch {
    return new Response("Invalid signature", { status: 400 });
  }

  if (isKnownWebhookEvent(event)) {
    switch (event.type) {
      case "message.delivered":
        console.log(`Delivered to ${event.data.recipient}`);
        break;
      case "message.bounced":
        console.log(`Bounced: ${event.data.recipient}`);
        break;
      case "message.opened":
        console.log(`Opened by ${event.data.recipient}`);
        break;
    }
  }

  return new Response(null, { status: 200 });
}
```

`parse()` is asynchronous as of 0.2.0, so it must be awaited before you treat the payload as trusted.

Create the webhook in your [AhaSend dashboard](https://dash.ahasend.com) pointing at `https://my-worker.your-subdomain.workers.dev/webhooks/ahasend`, and copy its secret into the `AHASEND_WEBHOOK_SECRET` secret exactly as shown, including the `aha-whsec-` prefix.

## Going Further

- **Templating**: pass `substitutions` per recipient and use `{{ variable }}` in the subject or body.
- **Batch sends**: `recipients` accepts up to 100 entries; each one gets a separate, individually-substituted message.
- **Your own idempotency keys**: pass `{ idempotencyKey: "order-123" }` as the second argument to `send()` to dedupe against your own identifiers.
- **Attachments**: pass `attachments: [{ data, content_type, file_name, base64: true }]`. Set `base64: true` for binary files such as PDFs.
- **Queues**: for bursts, push the send onto a [Cloudflare Queue](https://developers.cloudflare.com/queues/) and send from the consumer, so a slow upstream never holds the request open.

See the [Node.js SDK guide](/guides/nodejs-sdk) for client configuration in depth, and the [API reference](https://ahasend.com/docs/api-reference) for every endpoint the SDK exposes.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Constructor throws about an unsupported environment">
    You are on `@ahasend/sdk` 0.1.0, which refuses edge runtimes. Upgrade to 0.2.0 or later, where workerd is a supported runtime and no `nodejs_compat` flag is needed.
  </Accordion>
  <Accordion title="Webhook verification always returns 400">
    Three usual causes: the body was read with `request.json()` and re-serialized, which changes the byte layout, so always verify `await request.text()` first; `parse()` was called without `await`, so the rejection never surfaced; or the secret is missing its `aha-whsec-` prefix.
  </Accordion>
  <Accordion title="401 AhaSendAuthenticationError">
    Workers have no `process.env`. Read the key from the `env` argument, and confirm the secret is set with `wrangler secret put` for production and in `.dev.vars` locally.
  </Accordion>
  <Accordion title="400 error mentioning the from address">
    The `from` address must belong to a verified sending domain on your account. Check domain status in the dashboard.
  </Accordion>
</AccordionGroup>
