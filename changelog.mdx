<Update label="October 2026">
#### New Features

- **[Transactional templates](/send-api/templates) in API v2.** Create, update and delete templates, work on a draft, publish it, and read or restore published versions. Send a template with [Create Template Message](/api-reference/messages/create-template-message): each recipient gives its own values for the template's variables.
- **Transactional templates in the dashboard.** Under Transactional → Templates, design a template with the Simple Editor or the Advanced Editor, or upload your own HTML file or a zip with its images. Each template has its own page with its ID, its variables, a sample API request, a preview with your sample values, a test send, a default sender and subject, and its delivery statistics for the last 30 days. Your edits go to a draft. API sends keep using the published version until you click Publish, and the last 50 published versions can be previewed and restored.
- **[Campaigns](/api-reference/campaigns/overview) and [campaign templates](/api-reference/campaign-templates/get-campaign-templates) in API v2.** Create a draft campaign from MJML, HTML or a campaign template, check it, send a test, schedule or send it, and read its statistics and recipients.
- **Saved campaign templates.** Save a campaign's design as a template under Marketing → Templates and start new campaigns from it. Each campaign keeps its own copy, so a later change to the template does not change campaigns you already made.
- **[Contacts](/api-reference/contacts/overview) and [lists](/api-reference/lists/overview) in API v2.** Manage contacts, add them to lists in batches and read each list's members.
- **Sending type for domains.** Each domain is transactional or marketing. Choose the type that matches the mail you send from it. See [which sending type to use](/deliverability#which-sending-type-should-my-domain-use).
- **[One-click unsubscribe](/campaigns/unsubscribe).** Mail from a marketing domain gets `List-Unsubscribe` and `List-Unsubscribe-Post` headers. Put `{{unsubscribe_url}}` in any message to add the same link to its body.
- **[Daily marketing limit](/campaigns/marketing-limit).** Marketing mail of each account has a daily limit. Campaigns above it continue on the next days; API and SMTP marketing mail above it waits about a day and then fails.
- **[Paused domains](/domains#why-is-sending-paused-on-my-domain).** AhaSend can pause one domain when too many of its recent emails bounced, while the account's other domains keep sending. A parent account can [unpause a sub-account's domain](/api-reference/sub-accounts/unpause-sub-account-domain).
- **New API key [scopes](/api-reference/scopes)**: `contacts:*`, `lists:*`, `campaigns:*`, `templates:write` and `templates:delete`. Keys with `*` have them all. Keys with the `templates` scopes also manage campaign templates.
- **"View in browser" link for campaigns.** Add the link from the editor's variable menu. It opens the email as the recipient got it, after the campaign is sent. Opens and clicks on this copy are not tracked.
- **Right-to-left emails.** Both editors can set the direction of the whole email or of parts of it, for Arabic, Hebrew, Persian and other right-to-left languages.
- **Campaigns, contacts and lists for every account.** The dashboard has a new sidebar with Transactional, Marketing, Developers and Settings sections. Old links and bookmarks open the new pages.
- **Dashboard times in your time zone.** Charts, daily totals, report times, date filters and CSV exports use the time zone in your profile (Profile → Timezone), or UTC when none is set. Billing periods stay in UTC.
- **[Go SDK](/guides/go-sdk) v0.5.0 and [Node.js SDK](/guides/nodejs-sdk) `@ahasend/sdk` 0.5.0.** Both cover the contacts, lists, segments, campaigns, campaign templates and transactional templates APIs, template sends, domain sending types and the sub-account domain unpause, the new webhook settings and events, and Simple Editor designs as AhaML. Install them with `go get github.com/AhaSend/ahasend-go@v0.5.0` or `npm install @ahasend/sdk@0.5.0`.
- **[AhaSend CLI](/cli) v0.3.1.** v0.3.0 adds `contacts`, `lists`, `templates` and `campaigns` commands, and builds for Linux and Windows on ARM64. v0.3.1 changes no command. Install it with Homebrew, Scoop, npm, an install script, or a .deb or .rpm package; see [Installation](/cli/installation).
- **[MCP server](/mcp-server) for AI tools.** Connect Claude Code, Claude.ai, ChatGPT, Cursor, VS Code, Codex, Mistral Vibe and other AI tools to your account at `https://mcp.ahasend.com/mcp`. The agent can send email, find out why an email failed, set up domains, build templates, and manage contacts, lists and campaigns. You do not create or copy an API key: you log in through the browser, choose the account (a sub-account too), and choose what the agent may do. Use the Read-only, Developer, Marketer or Full preset or pick single permissions, and optionally limit the connection to some domains or to sandbox sending.
  - Each connection is an API key. The API Keys page names the tool and the user who connected it, and you can change its permissions or delete it there at any time.
  - The agent cannot read received email unless you turn this on for the connection. A campaign is sent only after you confirm it in your AI tool.
  - A connection ends when its user loses access to the account, and when the tool does not use it for 30 days.
  - The **Connect an AI tool** button on the API Keys page shows the setup steps for each tool, with one-click install for Cursor and VS Code.
- **[SMTP on port 465](/smtp#does-ahasend-support-port-465).** `send.ahasend.com` accepts SMTP on port 465 with implicit TLS, for clients and devices that cannot use STARTTLS. Port 465 accepts AUTH PLAIN and AUTH LOGIN. Ports 25, 587 and 2525 with STARTTLS are unchanged. The SMTP credential page shows port 465 too.
- **Save a list search as a new list.** On a list page, search or use advanced search, then click **Save as new list** to put the matching contacts on a new list. Send a campaign to that list to reach only those contacts. Each contact keeps its status, so an unsubscribed contact stays unsubscribed on the new list. The contacts are copied in the background, and the new list's page shows when the copy is done. The new list is separate from the original: later changes to the original list do not reach it.
- **[AhaSend Markup (AhaML)](/send-api/ahaml) for Simple Editor designs.** The API reads and writes a Simple Editor design as AhaML in `content.markup`, on transactional templates, campaign templates and campaigns. Read a design, change it and send it back; the dashboard editor opens what you write. A refused write lists each problem with its line and column. Designs with an HTML block read with a `markup_error`, and the Simple Editor no longer makes new HTML blocks.
- **[Get Published Template](/api-reference/templates/get-published-template).** Returns the copy of a template that sends use, with the variables each recipient must give. Read it to build a send.
- **Segments.** Under Marketing → Segments, build a group of contacts from rules: contact fields and the signup date, list membership, the campaigns a contact received, opened or clicked, how many of them, and birthday or anniversary rules on date fields (a month, or a date in the next days). A segment's members stay up to date as your contacts, lists and campaigns change. API v2 manages segments too, with the new `segments:read`, `segments:write` and `segments:delete` scopes.
- **Campaign audiences with segments and exclusions.** A campaign can go to lists and segments together, and leave out the contacts of other lists and segments. A contact in more than one of them gets the campaign once. A campaign to a segment reaches its contacts who are confirmed on a list or are on no list.
- **Contact webhooks.** New events tell your systems about changes to contacts: `contact.created`, `contact.updated`, `contact.deleted`, `contact.added_to_list`, `contact.removed_from_list`, `contact.subscribed`, `contact.unsubscribed` and `contact.complained`. A webhook created through the API needs a key that can read contacts, and lists for the list events.
- **Campaign unsubscribe and complaint webhooks.** `message.unsubscribed` and `message.complained` say which campaign email made a recipient unsubscribe or report spam, and how they unsubscribed (one-click or the link).
- **[Suppression webhooks](/integrations/webhooks) for every change.** `suppression.created` also comes for suppressions you create through the API and for unsubscribes from transactional email, and the new `suppression.deleted` comes when a suppression is deleted. Both say who made the change in `origin`.
- **Choose whose changes a webhook gets.** A webhook's `origins` limits the contact and suppression events it gets to changes made by recipients, through the API, in the dashboard or by AhaSend (`recipient`, `api`, `dashboard`, `system`). For example, leave out `api` so your own API writes do not come back to you as events.
- **CSV imports say when values are wrapped in quote marks**, per column and with an example, as an export from a JSON column can leave them. The values are stored as written, so rules that compare them may not match.

#### Changes

- **Breaking: [Get Template](/api-reference/templates/get-template) returns the working copy**: the template's draft while it has one, and its published copy otherwise. So you can read a template, change it and send it back to [Update Template](/api-reference/templates/update-template). While a draft exists, its `updated_at` can differ from the one [List Templates](/api-reference/templates/get-templates) shows. To build a send, read [Get Published Template](/api-reference/templates/get-published-template). The draft read, `GET /v2/accounts/{account_id}/templates/{template_id}/draft`, is removed; [Discard Template Draft](/api-reference/templates/discard-template-draft) stays.
- **Breaking: API v2 HTML-escapes substitution values in the HTML and AMP bodies**, as v1 and campaigns already do. A value of `<b>Ann</b>` now shows as that text, not in bold. To insert a value as HTML, write `{{ name|safe }}` in your content. If your code escapes values itself, stop doing so, or they are escaped twice. The subject, the headers and the text body get values as they are. See [substitutions](/send-api/send-email).
- **Breaking: AhaSend CLI v0.3.0 changes exit codes, input checks, prompts, flag defaults and output.** Read the [release notes](https://github.com/AhaSend/ahasend-cli/releases/tag/v0.3.0) before you upgrade scripts that use v0.2.0.
- **API v2 refuses some headers with `400`**: a custom header name that is not a valid header name (for example one with a space or a colon), and a substitution value with a line break that would end up in a header, such as the subject or a display name.
- **API v1 and v2 drop the custom headers `X-Campaign`, `X-CUSTOMER-ID`, `X-Subscriber-ID` and `X-Schedule-ID`.** The send succeeds without them. A v1 sandbox key always sends sandbox mail, whatever headers the request carries.
- **A campaign needs an unsubscribe link before it can be scheduled**: `{{ unsubscribe_url }}` in its design, in the dashboard and in the API. Campaigns that are already scheduled or sending are not affected.
- **A spam complaint about a campaign ends the contact's subscription to that campaign's list** and adds no suppression, so transactional mail to the address continues. A complaint about transactional mail still suppresses the address.
- **API error messages say "paused" in place of "suspended"** for accounts and domains.
- **Campaign reports count only bounced and failed recipients as bounces.** Mail that expires before AhaSend ever tried to deliver it ends as failed and adds no bounce.
- **Campaign open and click rates are now unique recipients out of delivered emails**, without bot opens and clicks. The click rate was clicks divided by opens before, and could pass 100%. Reports of earlier campaigns show the new rates too.
- **A list's subscriber count now shows the contacts a campaign can reach.** Bounced, invalid and unsubscribed contacts are left out, in the dashboard and in the API's `contact_count`. The Lists page also shows the total number of contacts on each list.
- **Unsubscribes and spam complaints are protected suppressions.** [Wiping suppressions](/api-reference/suppressions/wipe-suppressions) keeps them, and the dashboard marks them as protected. You can still delete one at a time.
- **Renaming a contact field changes only its label.** Its key, which templates, saved searches and the API use, stays the same.
- **Pause notices explain the reason.** When an account is paused, the dashboard and the email give the reason and the next steps.
- **Some campaign actions are refused earlier**: scheduling less than a minute ahead, scheduling when the sender domain is not verified or is paused, and scheduling when no contact on the chosen lists can get the campaign. The message says which one applies. A reply-to address must be a plain address, without a name.
- **Messages record their template.** In API v2, a message sent from a transactional template carries its `template_id`.
- **The contact CSV export writes dates in your time zone, with the UTC offset.** If you read this file with your own code, check how it reads dates.
- **New legacy (v1) API keys can no longer be created.** Existing v1 keys keep working. Create an API v2 key for new integrations.
- **An account name made only of spaces is refused**, in onboarding and on the account page.
- **API keys have a new permission list in the dashboard**, the same one as the MCP connection page. When you create or edit a key, each group of permissions has a No access, Read or Write switch, and a click on a group shows its single permissions. Quick buttons set Full access, Sending only or Read-only. Each permission that applies to a sending domain is allowed for all domains or for the domains you choose, with a filter when the account has many domains. Choosing "only these domains" without picking a domain is refused.
- **Saving an API key removes permissions that no longer apply**: those for a domain that was removed from the account, and those for a feature the account no longer has. The edit page lists them before you save.
- **API v2 refuses some display names with non-ASCII characters on sends with substitutions or a template.** When `from.name`, `reply_to.name` or a recipient's `name` has non-ASCII characters, AhaSend fills plain variables such as `{{ first_name }}` in it itself. Any other template syntax in such a name, such as a filter or a tag, fails the send with `400`. A transactional template's default sender name that breaks this rule is refused when you save the template. Names with only ASCII characters are not affected.
- **API v2 drops a custom `AhaSend-To` header, and [Create Conversation](/api-reference/messages/create-conversation) drops a custom `To` header.** The `to` field sets the `To` header.
- **The SMTP credential page shows one server, `send.ahasend.com`.** `send-us.ahasend.com` keeps working.
- **API v2 rate-limit `429` responses carry a `Retry-After` header** with the number of seconds to wait before you retry. See [rate limits](/api-reference/rate-limits).
- **API v2 checks every message with the template engine before it sends it.** [Create Message](/api-reference/messages/create-message), [Create Template Message](/api-reference/messages/create-template-message), [Create Conversation](/api-reference/messages/create-conversation) and [Test Campaign](/api-reference/campaigns/test-campaign) refuse content that cannot be rendered with a recipient's values with `400`, and send nothing of the request. When the check cannot run right now, they answer `503` with a `Retry-After` header; send the same request again after that delay. See [API errors](/api-reference/errors#503-service-unavailable).
- **A transactional template's `variables` say what to send for each variable.** Each one has a `kind`: `value` for text in the email, `condition` for a value that shows or hides a part, and `list` for an array that repeats a part. A `list` variable's `item_fields` name the fields of each element. See [kinds of variables](/send-api/templates#kinds-of-variables).
- **A campaign that could not be checked right now has the [issue](/api-reference/campaigns/overview#issues) `text_unchecked`.** Nothing is known to be wrong with it. Check it again in a moment.
- **A recipient of a campaign sent to a segment unsubscribes from all your marketing email**, and a spam complaint does the same, because a segment is not a list they joined. A recipient of a campaign sent to a list still leaves only that list.
- **Contact date fields are read day first.** Imports and the dashboard read `05/12/1990` as 5 December 1990, not 12 May. A month-first date that cannot be read day first, such as `12/25/1990`, is no longer stored. Dates such as `1990-12-05` are read as before.
- **The Simple Editor makes no new HTML blocks.** HTML blocks that a design already has still show, send, and can be edited or deleted.
- **Logging out asks for one click.** Opening the logout address shows a page with a **Log out** button. The **Log out** item in the menu works as before.

#### Improvements

- **The old DKIM key is revoked a week after a rotation.** On managed DNS domains, AhaSend publishes an empty (revoked) key for the old signing key and deletes its private key, so an old key can no longer pass DKIM. Domains with manually set up DKIM are not affected.
- **Campaign list checks finish faster on large lists**, so the decision before sending is based on more of the checked contacts.
- **Campaign list checks no longer count addresses on catch-all domains as bad.** A catch-all domain accepts mail for any address, so the check cannot confirm the mailbox. These contacts still get the campaign, and the list check on the campaign report shows them as Catch-all, next to Risky. A campaign to a large list where most addresses are on catch-all domains goes to manual review.
- **Campaign report breakdowns load faster on large campaigns.** They are counted in the background and show when they were last updated. The bounce and status lists page with Previous and Next, and no recipient is repeated or skipped.
- **Advanced search on a list is more complete.** Full names match, "is empty" also finds contacts that never had the field, and date filters accept relative dates such as "7 days ago".
- **See a sent campaign's email in full.** On a sent campaign's page, the design thumbnail has a **View email** button that opens the email in a new tab.
- **CSV contact imports accept an `Email Address` column**, as in Mailchimp exports. Before, the column had to be named `email`. From a Mailchimp export, import only the subscribed contacts file: the unsubscribed and cleaned files have no status column, so their contacts would be imported as subscribed.
- **When MJML cannot be compiled, the Advanced Editor says why**, with the compiler's message.
- **Dark mode is easier to read.** Links and blue buttons, disabled ones included, are lighter, and selected text is visible, in dark mode and on the dark sidebar and page headers. The stat cards on a campaign report all have the same height.

#### Bug Fixes

- **Fixed [Reputation Shield](/security/reputation-shield) rejecting mail to real mail providers**, such as Hotmail, Outlook, Live, MSN, Proton and Tutanota, for a short time in early October. A public list of temporary-mail domains we use had started to include them.
- **Fixed automatic DKIM rotations starting late for some domains**, mostly on plans that rotate more often.
- **Fixed API v2 always reporting managed DKIM records as `propagated: false`**, even on fully set up domains.
- **Fixed managed DNS records sometimes showing "Issue detected" for up to 15 minutes** after we published them, when our DNS provider briefly limited our requests.
- **Fixed campaign list checks counting addresses they could not check as bad**: when the address check service was busy, when the check timed out, or when the receiving mail server asked to try again later or blocked the check. Those contacts keep their status, still get the campaign, and a later list check can check them again.
- **Fixed many spam complaints from Yahoo and Microsoft not being recorded.** Complaints now appear in your statistics, and the addresses are handled as described above.
- **Fixed a bounce or a complaint erasing a contact's unsubscribe from a list.** A bulk add or a CSV re-import also no longer subscribes people who left a list again.
- **Fixed updating a webhook through API v2 failing with `500`** for webhooks limited to some domains. This affected requests from 5 to 12 October.
- **Fixed campaign report exports (CSV and PDF) returning "not found".**
- **Fixed advanced search on the list page not applying its filter.**
- **Fixed the Send Campaign button on a list page returning "not found".** It now starts a campaign for that list. When a search narrows the list, the campaign window says that the campaign goes to the whole list.
- **Fixed a campaign's reply-to address not being removable.**
- **Fixed the average delivery time cards on the home page showing 0** for accounts with no delivery window set.
- **Fixed changing a domain's settings through API v2 not updating its `updated_at`.**
- **Fixed an API v2 send reporting recipients as sent that were never sent** when the client closed the connection during the request. A retry with the same idempotency key got the same wrong answer. A send now finishes once it has started. This also applies to template sends.
- **Fixed a refused API key create losing your choices.** The form came back closed, and opening it again started from Full access, so a key with fewer permissions could be created with all of them. The form now opens again with the name, [IP allow list](/security/ip-allow-lists), permissions and sending mode you entered, and shows why the key was not created.
- **Fixed an IP allow list change being refused again and again** after a save that needed you to confirm it was you. The form did not ask for the confirmation a second time. This affected the API key and SMTP credential forms.
- **Fixed long sender names with non-ASCII characters getting an extra space in API v2 sends**, in `From` and `Reply-To`. For example, "Gymnasiums" arrived as "Gym nasiums".
- **Fixed names in `to` on [Create Conversation](/api-reference/messages/create-conversation) going out unencoded** when they had non-ASCII characters. Some mailbox providers, such as GMX, rejected these messages.
- **Fixed API v2 attachments losing their file name** when the request set `content_disposition`.
- **Fixed MJML that closes a tag with `/>`, such as `<mj-image ... />`, failing with "Failed to render MJML"** in the Advanced Editor. MJML exported from Klaviyo is written this way.
- **Fixed `ahasend routes listen --recipient` answering `403` for a recipient domain the account does not have.** The API now answers `400`, and the message says the domain is not found in the account.
- **Fixed an open or a click turning a bounced message back into "Opened"**, and a later open turning a clicked message back into "Opened".
- **Fixed out-of-band bounce reports being matched by headers that any sender can set.** A report now matches only a message AhaSend delivered, and suppresses only that message's recipient. Real bounce reports that were not matched before are matched now.
- **Fixed some bounced messages losing their "Non-delivery report" link** when the report gave no reason text.
- **Fixed a campaign list check in one account blocking the same address in other accounts.**
- **Fixed the live event stream of `ahasend webhooks listen` and `ahasend routes listen` sending events that the API key's scopes do not allow.**
- **Fixed webhooks limited to some domains getting the opens and clicks of every domain**, and click webhooks of campaign links never being sent.
- **Fixed `suppression.created` being sent again** for a repeat bounce or unsubscribe of a suppression that did not change.
- **Fixed campaign webhook events being dropped** after the campaign's domain was deleted.
- **Fixed a transactional template's `variables` leaving out names** that only its show-if rules test or its repeat blocks loop over.
- **Fixed the Simple Editor's preview of an HTML block cutting off wide emails**, or staying empty while a slow image loaded. The preview runs no scripts.
- **Fixed a paused account not being able to set the sending type of its domains**, which the pause notice asks for.

<Update label="September 2026">
#### Changes

- **The account and sub-account `website` field now accepts a domain or an http(s) URL everywhere**: the dashboard, onboarding, [`PUT /v2/accounts`](/api-reference/accounts/update-account), and the sub-account [create](/api-reference/sub-accounts/create-sub-account) and [update](/api-reference/sub-accounts/update-sub-account) endpoints. The value is stored as the bare domain, so `https://acme.com/team` is saved as `acme.com`. Values that are not web addresses (such as `ftp:`, `mailto:` or `javascript:`) and hosts that are not valid domain names are now rejected. Existing websites are not changed until they are next edited.
- **[Inbound routes created through the API](/api-reference/routes/create-route) now get the same signing-secret format as routes created in the dashboard**: `<prefix>-rsec-` followed by 64 characters that may include letters, digits, `_` and `-`. If your code checks the length or characters of [route secrets](/integrations/routing#signature-verification), update it to accept this format. Existing secrets are unchanged and keep working.
- **The `AhaSend-Schedule` header is now reserved in API v2 sends.** If you include it in a message's custom `headers`, it is dropped. To schedule a message, use the API's [scheduling fields](/api-reference/messages/create-message).
- **Messages that expire after running out of retries now suppress the recipient only when the receiving side caused the failure.** A message that expires without ever being attempted no longer suppresses the address. Messages to domains that really don't exist are still [suppressed](/bounces#suppression-duration).
- **After you [create an API key](/send-api/credentials#creating-api-keys), its secret is shown once and is no longer placed in the page address**, so it does not end up in your browser history (previously it was included in the URL). Reloading the page will not show it again, so copy it when it first appears.

#### Improvements

- **[Validation errors](/api-reference/errors#validation-errors) from `PUT /v2/accounts` and the sub-account endpoints are now clearer.** They name the JSON field, list every problem in the request and say what to send, instead of a generic "invalid request body" or internal validator text.
- **Delivery events are recorded more reliably during heavy sending.** Events are confirmed only after they are stored, so they are no longer lost during service restarts or traffic spikes.
- **The message details page now keeps explaining why a message is waiting**, for example that your account has reached its sending rate limit, for as long as it waits. Before, the explanation could disappear after a few minutes.
- **The cookie consent banner on the dashboard is now served from AhaSend's own domain**, so it loads even when a third-party CDN is blocked.

#### Bug Fixes

- **Fixed temporary failures on AhaSend's side adding valid recipients to your [suppression list](/bounces#why-was-my-email-suppressed)** and disabling campaign subscribers. These messages still show as bounced. Recipients are now suppressed only when the receiving mail server or the recipient's own domain rejects the address.
- **Fixed spam complaints from mailbox providers not being processed** when the original email used a character set other than UTF-8. Recipients who complain are now suppressed and unsubscribed from your lists as intended.
- **Fixed domains that point their inbound (MX) host at AhaSend with a CNAME showing the MX record as not configured** and being unable to create [inbound routes](/integrations/routing#prerequisites). Inbound mail to these domains kept arriving throughout.
- **Fixed a short DNS lookup failure marking a correctly configured domain's records as missing.** This could briefly mark a domain as [unverified](/domains#why-is-my-domain-not-verified) and pause its sending or receiving. We now keep the last known status until DNS gives a clear answer, and try several resolvers before deciding a record is really gone.
- **Fixed the checkout pay button spinning forever** when an ad blocker or browser tracking protection blocks Stripe's payment form. You now see a clear message explaining what to do.
- **Fixed choosing a plan on the Billing page sometimes failing** because two checkout sessions were started at once.
- **Fixed resending a verification email, requesting a password reset and changing your email address showing "Internal server error"** when the request had actually succeeded. Expired-link messages now say a new email was sent only when one really was.

</Update>

<Update label="August 2026">

#### New Features

- **[Official TypeScript / JavaScript SDK](/guides/nodejs-sdk)**: [`@ahasend/sdk`](https://github.com/AhaSend/ahasend-ts) is now available on npm (`npm install @ahasend/sdk`). It covers the full API v2: messages, domains, API keys, webhooks, statistics, suppressions, inbound routes, SMTP credentials, account members and sub-accounts, with TypeScript types included, automatic idempotency keys on create calls, retries, rate-limit handling and pagination helpers. A separate `@ahasend/sdk/webhooks` entry point verifies webhook signatures and parses all event types, with adapters for Express, Fastify and Next.js. It runs on Node.js 22+, Deno, Bun, Cloudflare Workers and Vercel Edge. It is a server-side SDK and is still v0.x, so pin an exact version in production.
- **[Delivery Attempt Details in Webhooks](/api-reference/webhooks/message-bounced)**: `message.delivered`, `message.bounced` and `message.transient_error` webhooks now include a `delivery_attempt` object with the SMTP result behind the event: `smtp_code`, `enhanced_status_code`, the receiving server's `response`, a plain-English `description`, the bounce `classification`, and the SMTP `command` stage. The field is additive and is left out of events that are not the result of a delivery attempt. Test webhooks and sandbox sends include a representative sample, so you can build against the real payload shape.
- **See Why a Message Is Still Waiting**: The message details page now explains why an outbound message has not been attempted yet: that it is scheduled for a specific time (shown in your timezone), that your account has reached its sending rate limit, that deliveries to the recipient's mailbox provider are temporarily paused, or that deliveries are being paced.
- **Find Messages That Were Ever Deferred**: A new "Has deferred attempts" filter on the Messages page finds messages that hit a temporary delivery failure at any point, even if they were delivered afterwards.
- **Readable Delivery Diagnostics**: When a delivery problem happens on our side of the connection, the delivery attempts on the message details page, campaign bounce messages and the campaign recipient export now show a clear sentence instead of raw mail-server internals. For example "DNS lookup for the recipient domain gmail.con failed: NXDOMAIN (the domain does not exist)" or "The destination mail server did not respond to MAIL FROM within 10s". Responses from recipient mail servers are still shown exactly as received. Applies to newly logged attempts.

#### Changes

- **Outbound messages waiting for their first attempt now show as "Queued"** in the dashboard instead of "Received". Inbound messages still show "Received". API responses and webhooks are unchanged.
